# Discover → Design → Deploy → Review

本篇是 FDE 现场工作的**主骨架**。后面所有方法论文章都挂在这四个阶段上。目标：你能说清每阶段的**入口、动作、出口、产物**，并避免阶段跳跃（最常见的翻车是 Discover 没做完就 Deploy）。

---

## 1. 总览

```mermaid
flowchart LR
  D1[Discover发现]
  D2[Design设计]
  D3[Deploy部署]
  R[Review复盘]
  D1 --> D2 --> D3 --> R
  R -.->|新范围或下一场景| D1
```

| 阶段 | 一句话 | 核心问题 |
|------|--------|----------|
| Discover | 弄清真相 | 谁痛？被什么指标衡量？约束是什么？ |
| Design | 变成可执行计划 | 做什么、不做什么、如何证明成功？ |
| Deploy | 在约束内实现并上线 | 权限、数据、集成、培训、观测齐了吗？ |
| Review | 学习与杠杆 | 有效吗？为何？怎样复用/反馈产品？ |

AI 项目特别容易在 Deploy 前假装 Design 完成——**没有 Eval 计划就不算 Design 完成**。

---

## 2. Discover（发现）

### 入口条件

- 有赞助人（sponsor）或至少一名业务 champion
- 能接触到真实用户或一线操作者（不是只有 IT 转述）

### 关键动作

1. **干系人地图**：出资、使用、否决（安全/法务/IT）、维护
2. **现状工作流**：用时、工具、例外、失败代价
3. **数据与权限现实**：在哪、能否出域、质量、新鲜度
4. **成功的可观测定义**：若只能选一个指标，是什么？
5. **非目标**：明确「这次不解决什么」

### 出口产物

- 发现纪要（问题陈述、用户、指标、约束、风险、开放问题）
- 初步范围假设（待 Design 确认）

模板：[发现访谈提纲](../08-工具箱与清单/发现访谈提纲.md)

### 出口检查

- [ ] 能用一句话说清「为谁、解决什么可测问题」
- [ ] 知道最大技术/组织风险各一条
- [ ] 赞助人认可问题陈述（哪怕方案未定）

---

## 3. Design（设计）

### 入口条件

- Discover 出口检查通过
- 已知数据抽样或等价了解

### 关键动作

1. **方案选项**（至少 2 个）：含「不做 LLM」选项
2. **架构草图**：数据流、权限、人机回环、失败降级
3. **Eval 设计**：golden set 从哪来、量规是什么
4. **试点切片**：用户群 × 文档/流程子集 × 时间盒
5. **成本与延迟预算**
6. **安全与合规审查清单**

决策辅助：[架构决策树](../03-AI落地/架构决策树.md)

### 出口产物

- 设计一页纸 / 简短设计文档
- POC/Pilot 验收标准（可勾选）
- 风险登记与缓解

模板：[POC 验收表](../08-工具箱与清单/POC验收表.md)

### 出口检查

- [ ] 成功标准可测，且与业务指标挂钩
- [ ] 有明确非目标与时间盒
- [ ] 安全/IT 已看到权限与数据流（至少知情）

---

## 4. Deploy（部署）

### 入口条件

- Design 验收标准已书面确认
- 环境、密钥、网络路径已打通或有明确 blocker 升级

### 关键动作

1. 实现与集成（迭代，但每次迭代可演示）
2. 评测闭环：改 → 跑 eval → 看失败案例
3. 权限、审计、日志、告警
4. 用户培训与 Runbook
5. 分阶段 rollout（影子模式 → 建议模式 → 自动模式等）
6. 交接计划（谁值班？）

清单：[生产 Go-Live 清单](../08-工具箱与清单/生产Go-Live清单.md)、[生产化清单](../03-AI落地/生产化清单.md)

### 出口产物

- 生产或试点环境中的运行系统
- 观测看板与 on-call 说明
- 用户启用材料

### 出口检查

- [ ] 达到书面验收线，或有明确「未达线但不扩大范围」的决策
- [ ] 回滚路径可用
- [ ] 至少一名客户侧人员能独立完成主路径操作

---

## 5. Review（复盘）

### 入口条件

- 试点或生产运行过一个约定窗口（如 2–4 周）

### 关键动作

1. 对照指标：量与质（含失败案例抽样）
2. 用户访谈：采用障碍
3. 技术债与成本复盘
4. **模式化**：哪些可进解决方案库？
5. **产品反馈**：平台缺什么？
6. 决定：扩大 / 维持 / 停掉 / 改方向

### 出口产物

- 复盘文档（含数据）
- 更新后的 Playbook
- 给产品/领导的简报

### 出口检查

- [ ] 有「下一轮 Discover」的输入，或明确结项
- [ ] 知识不独享在你个人笔记本

---

## 6. 阶段节奏与并行

现实中阶段会重叠，但遵守：

- **允许**：Deploy 早期同时补 Discover 细节
- **禁止**：用 Demo 欢呼跳过 Eval；用「先做了再说」跳过安全
- **时间盒**：Discover 1–2 周、窄 Pilot 2–6 周是常见量级（视企业采购与数据就绪度而变）

---

## 7. 示例：把「智能客服」塞进 DDDR

| 阶段 | 例子 |
|------|------|
| Discover | 真正痛点是「首响」还是「一次解决率」？工单系统能否写回？ |
| Design | 先做「检索知识库 + 坐席助手」而非全自动回复；定义 50 条黄金问答 |
| Deploy | 影子模式建议回复；坐席一键采纳；记录采纳率 |
| Review | 采纳率 35%→ 分析拒绝原因；扩大品类或停掉自动发送 |
