# 咨询思维与软技能栈

> 整理自 Awesome FDE Phase 3 与「Soft Stack」。  
> FDE 是「技术外交官」：人的问题不解，技术方案到不了生产。  
> 与 [客户沟通](./客户沟通与阻力处理.md)、[需求发现](./需求发现与问题拆解.md) 配套。

---

## 1. 核心心智

| 框架 | 用法 |
|------|------|
| **MECE** | 互斥且穷尽：把「AI 战略」拆成不重叠技术任务 |
| **金字塔原理 / BLUF** | 先结论；高管要「所以呢」再听「怎么做」 |
| **80/20 范围** | 找解决 80% 痛点的 20% 功能；避免镀金 |
| **五个为什么** | 发现根因，而非表面功能 |
| **需求翻译** | 「要更高效」→ 可执行的技术 PRD / 工单 |

**Delta（差距）概念**（Palantir 语境）：产品开箱能力与客户使命成功之间的缺口——FDE 的胶水工程就建在这里。

---

## 2. 诊断三问（客户要功能时）

1. **权威源在哪？** 若在某人桌面 Excel，项目已高风险  
2. **不作为的代价？** 定义优先级与赞助力度  
3. **Day 2 谁运维？** 无内部 owner，项目会在你离开后死亡  

---

## 3. 前线发现检查清单（写代码前）

### 行政与政治

- [ ] Champion（内部推动者）是谁？  
- [ ] Blocker（IT/法务等）最可能是谁？  
- [ ] 成功是降延迟、提准度，还是减人头？  

### 数据与安全

- [ ] 分级：PII / PHI / Secret？  
- [ ] 摄入：流式还是批？  
- [ ] 是否要 VPC SC / DLP？  

### 基础设施

- [ ] 云项目角色是否足够？  
- [ ] 私有集群 / VPN / Interconnect？  
- [ ] GPU 配额是否够用？  

完整模板见 [现场勘察模板说明](../08-工具箱与清单/现场勘察与范围文档.md)。

## 4. 信任公式（Trusted Advisor）

\[
Trust = \frac{Credibility + Reliability + Intimacy}{Self\text{-}Orientation}
\]

降低「自我导向」：聚焦客户赢，而非堆产品功能清单。

| 产物 | 作用 |

| **SOW** | 防范围蔓延的护栏 |

## 6. 红旗（发现期立刻升级）

1. 「数据两周后就好」（几乎从不）  
2. 「我们这边不需要项目经理」（易失焦）  
3. 「先随便 on-prem 跑跑」（常掩盖对云的深层不信任，后期会卡死）
