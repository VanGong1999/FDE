# 价值观与招聘经理操练（Values & Hiring-Manager Drills）

> 原文来源：The Forward Deployed — Interview Practice（https://www.theforwarddeployed.io/interview-practice）的 Values & Hiring-Manager Drills 一节，全文翻译整理。本篇是「行为面STAR题库.md」的**操练层**：题库给出题型与故事卡片，本篇给出价值观轮（values round）与招聘经理对话（hiring-manager conversation）两轮的具体操练协议、失败故事四部分，以及「坏/好/优」对照，二者互补、不重复。

FDE 面试流程中有两轮，工程师们对它们的刻意准备最少，而这两轮都是可以被挂掉的：一轮是价值观轮（values round），"你为什么想来这里工作？"以及失败问题就在这里；另一轮是流程文档以它收尾的招聘经理对话（hiring-manager conversation）。价值观轮考察你的理由是否专属于这一家公司，以及你的失败故事在被追问的压力下是否仍然保持为一次失败。招聘经理对话考察你 résumé 上声称的 ownership，能否在你被细问决策、权衡与结果时依然站得住。《面试方法》（The Interview Method）承载了这两类问题的来源，以及关于每一条该把话说得多满的坦诚提示；本页则是这些操练（reps）的来源。

## 经得起追问的失败故事

失败问题是文档化的，它的意图也一样。Palantir 自家的面试建议直白地说："我们不是在钓一个成功故事。我们想听一次真正的失败。"这条指示听起来容易照做，却不断被违反，因为大多数准备好的失败故事都被设计成让讲述者显得好看，而一次追问就足以让它崩塌。

从选择开始。挑一个真实的失败，其中是你的决策造成了代价。你只是参与了响应的生产事故，是一个"打仗故事"；一个在你身边死掉的项目，是一份"天气预报"。这一轮要的是你做出的、事后被证明是错的那个决定。一旦有了它，故事需要四部分，按顺序讲：

1. **你当时做出的决策。** 你选择了什么，以及你当时知道什么：你掌握的信息、你承受的压力、你放弃的替代方案。讲述时不要让事后之明渗进来——如果开头就透露出你已经知道结局，后面的 ownership 就会听起来像在背稿。
2. **代价，在它落地之时。** 这个决策破坏了什么，要具体地说：跑在坏数据上的客户、被拖延的日期、花了一周清理的团队。一个说不出具体代价的失败是一次"差一点"，而"差一点"读起来就是伪装的成功。
3. **你当时做了什么。** 你是怎么发现的，你先分诊（triage）了什么，你在什么时候告诉了谁。这一部分是能力所在——承担一次失败和把它处理得好是可以兼容的，这一轮同时都在听。
4. **你持久地改变了什么。** 某种活过了那次事件、并随你而行的东西：你如今在这类决策之前会跑的一个检查项，你如今会问、而当时跳过了的一个问题。一句"以后要更小心"的决心，就是这一部分的缺失。

## 示例操练对话

下面阶梯式回答与追问对话中的候选人回答均为操练而杜撰。

## 坏 / 好 / 优 — 讲失败故事

**坏 — 一个伪装的成功。** "我最大的失败就是我工作太努力，对自己代码的标准太高。"或者它更隐蔽的表亲——那种"环境导致了失败"的故事：供应商掉链子了、需求在你脚下变了、重组杀死了项目。两者都拒绝了问题的前提——面试官要的是一个让你付出了代价的、你自己的决策，却听到了一句自夸或一份天气预报。面对如上文引语那样明确的建议，这个回答还表明：你不相信这家公司真的说到做到。

**好 — 一个真实失败，却止步于套话。** "我没先检查数据质量就承诺了一个迁移日期。我们晚了一个月，客户升级投诉了。我学到的教训是要更早沟通、提前验证假设。"决策是真的，代价是真的，讲述也是诚实的——这已经好过这一轮听到的大多数回答。但结尾把开头挣来的又还了回去："更早沟通"和"验证假设"是没有人会总结不出来的教训，所以它们没有携带任何证据，证明你这个人真的变了。

**优 — 决策、被认领的代价、以及一个扛得住追问的改变。** "我交付了一个客户的数据迁移，没有回滚路径。回滚计划本来在我自己的检查清单上；我把它砍掉了，因为干跑（dry run）很干净、而且我们进度落后，我判断这个风险可以接受。这是个错误的决定。迁移破坏了一小片干跑从未覆盖到的记录，客户的团队在坏数据上干了一整天，他们损失了将近一周用来对账，而我手工重建了状态。有两件事改变了并且一直没变：我每次都在迁移之前先写回滚步骤；而且我把一次干净的干跑当作关于'干跑覆盖率'的事实，而不是关于'迁移本身'的事实。" 这个回答与"好"的区别，在于它扛得住什么。被问到"以你当时知道的情况，那个更好的决定是否做得出？"这位候选人可以不用换立场就说"是"：清单项本来就在，覆盖率问题是当时可问的，而这个持久改变恰好就是当初能抓住它的机制。"好"讲出了过去的真相；"优"向面试官展示了防止重蹈覆辙的机制。

## 可能遇到的追问

一个好的面试官会给你一条出路，而这份"出路"本身就是测试。

**面试官：** "说句公道话，这听起来是流程失败了，而不是你——没有任何东西要求必须有回滚计划，也没有任何评审发现它缺失。"

**你：** "流程的缺口是真实的，而我在做决定时就知道它——回滚计划本来就在我自己的检查清单上，是我为了保住日期把它删掉了。如果当时存在一个强制步骤，那一周我也会为它申请例外；压力来自我自己。缺口让这个错误成为可能。是我的判断让它发生了，这也就是为什么我留下的修复属于我、随我而行，而不是活在某个团队的流程文档里。"

这一招：拒绝那条出路。一个提出把你的失败重新归因给流程的面试官，是在检查你故事里的 ownership 是不是装饰；接受这个重新归因，就一句话把"优"答案重新变回了"坏"那一档的伪装成功。你可以承认流程缺口是真实的——它通常确实是——同时守住那个决策，从而守住那次失败属于你。

## 操练工具箱（Rep Kit）

上一节把答案都印出来了，所以第一遍读完之后它什么都练不到。下面两个协议是无答案的操练。把每一个原样粘贴进一个能力足够的 AI 对话。第一个操练价值观轮：用《面试方法》里的"坏/好/优"来检验你的"为什么是这里"，用上面的四部分来检验你的失败故事。第二个操练招聘经理对话——流程结构把它文档化为整个流程收尾的那一轮，而它的材料就是你自己的 résumé。

### 价值观轮面试官

```
你是 Forward Deployed Engineer 面试流程中的价值观轮（values round）面试官。
人设：友善、不慌不忙、不为背稿式的回答所动。一次只问一个问题。

规则：
1. 先问我正在面试哪家公司，在我说出公司名之前不要开始。
   每次只跑一个完整的操练（rep）：先问"为什么是这里？"，
   再问失败故事，最后在我要求时给出评分。
2. 以"你为什么想来这里工作？"开场。然后追问它的"通用性"：
   取出我最强的一句话和我的整体论证，问其中每一项是否在换成
   另一家公司的名字后仍然成立。如果哪一项仍然成立，就指出来，
   让我把它替换掉，再继续。如果我陈述了一个关于"我在哪里创造
   价值"的论点，就压它一次——挑战它最薄弱的一环——然后再继续。
3. 然后让我讲一个失败故事——一个真实的、我自己的、有代价的。
   如果我给出的东西是伪装的优点、只有环境失败的故事、或是
   "我想不出来"，就指出来，并在追问之前要求我换一个故事。
   对真实的那一个，追问恰好两次：
   a. 给我一条出路：暗示这次失败其实是流程、环境、或是伪装的成功。
      如果我接受这条出路并重新定位故事，为此给我扣分。
   b. 压代价："具体来说，它让你付出了什么？"只接受具体的代价——
      时间、金钱、一个客户、一个人的信任。
4. 当我说"给我评分"时，对下面四项标准逐项打 PASS 或 FAIL，
   每项都引用我具体的某句话：(a) 我的"为什么是这里"是否专属这家
   公司，是否点出了真实的产品和客户（或某个具体部署或客户细分）；
   (b) 我是否陈述了一个你能去压的、关于"我在哪里创造价值"的论点，
   而它是否扛住了你的压；(c) 我是否点出了这份工作的一个代价并
   知情地接受它；(d) 我的失败是否在两次追问下仍然保持为一次失败。
   从严评分：典型的第一次操练至少会挂掉其中两项——如果一项都没挂，
   在表扬之前重新审视，而且绝不要因为我跟你争辩就软化评分。
5. 结束时只给一个下一轮要修的点。然后提供另一轮操练：
   把同一家公司讲得更好，或换一家新公司。
```

### 招聘经理

```
你是 Forward Deployed Engineer 面试流程中的招聘经理（hiring manager），
主持这个流程收尾的那轮对话。你的任务是弄清我 résumé 上的项目
是否名副其实。

规则：
1. 一次只处理一个项目。我会粘贴我 résumé 上一个真实项目的简短
   摘要；只基于我给你的内容以及你的提问引导出来的内容来工作。
2. 深挖，一次一个问题：
   a. 哪些决策是我的。留意用"我们"来掩盖"我"，每当你听到它在
      掩盖一个决策时，就问："*你*决定的是什么？"
   b. 权衡是什么——我放弃了什么，以及为什么那是当时正确的代价。
   c. 什么出了问题（开发或生产），以及我为此做了什么。
   d. 可度量的结果是什么，以及它是如何度量的。
   e. 现在我会有什么不同的做法。
3. 每当你听到模糊或不可验证的说法（"显著提升"、"快得多"、
   "团队很喜欢"），立刻标记它——当几个同时出现时，一次只排队
   标记一个——并要求给出具体的版本。在我给出具体版本或承认我
   没有之前，不要继续。
4. 当我说"给我评分"时，对下面四项标准逐项打 PASS 或 FAIL，
   每项都引用我具体的某句话：(a) ownership 是否清晰——由你能核查
   的具体细节支撑的"我"的陈述；(b) 一个我为之辩护而非否认的权衡；
   (c) 一个诚实的局限——某种出了问题或表现不佳的东西，毫无退缩地
   讲出来；(d) 一个用客户或业务的措辞、而非系统措辞陈述的结果。
   从严评分：典型的第一次操练至少会挂掉其中两项——如果一项都没挂，
   在表扬之前重新审视，而且绝不要因为我跟你争辩就软化评分。
5. 结束时只给一个下一轮要修的点。然后要下一个项目，
   或把同一个项目讲得更好。
```

## 这些操练留下什么

跑到一个通过的评分，这两个协议会收敛到两件值得写下来的产物：一段扛过了两次追问的失败故事段落，以及一段点出产品、客户、以及你接受的一份"角色代价"的"为什么是这里"段落。把两者都写下来，并把两者都当作易腐品对待。失败故事会在你反复讲述时漂移——每一次复述都会磨掉一点代价——而"为什么是这里"在构造上就专属某一家公司，所以不能复用。在那一轮面试的前一周，为每家公司重跑一次价值观协议，用你当前的段落作为开场答案。
