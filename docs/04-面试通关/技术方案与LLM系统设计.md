# 技术方案与 LLM 系统设计

本轮考察：在客户约束下设计**可落地、可评测、可运营**的系统。答法结构比堆名词重要。

---

## 1. 标准答法结构（15–20 分钟）

| 时间 | 板块 | 内容 |
|------|------|------|
| 2 min | 澄清 | 用户、目标指标、错误代价、数据驻留、是否可 HITL |
| 3 min | 范围 | 做什么/不做什么；试点切片 |
| 5 min | 架构 | 组件图：体验、编排、检索/工具、模型、护栏、观测 |
| 3 min | 关键设计 | 权限、eval、失败降级、成本延迟 |
| 2 min | Rollout | 影子→辅助→自动；门禁 |
| 2 min | 风险与演进 | Top 风险；何时微调/扩大 |

口头禅：「在假设 X 下我选 Y；若假设错则改 Z。」

---

## 2. 白板必画元素

```text
[用户/业务系统] → [网关鉴权] → [编排]
                      ↓
              [护栏] [RAG/工具]
                      ↓
                   [模型]
                      ↓
              [输出护栏/写回]
                      ↓
              [日志·Eval·告警]
```

指出 **ACL 强制点** 与 **HITL 点**。

## 3. 高频题库与答法要点

### A. 企业知识库助手

- 澄清：谁问、答错代价、文档权限模型  
- 主路径：RAG + 引用 + 拒答  
- 硬点：ACL、过期文档  
- Eval：分层黄金集 + 权限用例  
- Rollout：单部门助手  

### B. 客服自动回复

- 默认反对「第一天全自动对外」  
- 坐席助手 / 影子模式  
- 工单系统写回、升级路径  
- 指标：采纳率、一次解决率、有害建议率  

### C. 合同审核

- 拆条款类型；责任仍在人  
- 抽取 + 规则/对照模板 + HITL  
- 数据不出域  
- Eval：漏检 vs 误报权衡（按风险）  

### D. SQL/分析 Agent

- 主题域限定；只读副本  
- 强制解释与权限  
- 高危查询审批  
- 用金标问题测正确率  

### E. 多步办理 Agent（退款/改套餐）

- 固定工作流优先  
- 工具分级 + HITL  
- 审计轨迹  
- 红队：提示注入诱导转账  

### F. RAG vs Fine-tune

走 [架构决策树](../03-AI落地/架构决策树.md)：先穷尽 RAG/工具；微调要数据、治理、回滚故事。

### G. 评估「上线了吗」

答：离线黄金集通过线 + 线上采纳/差错 + 运营就绪（观测、值班、回滚）+ 书面门禁。

## 4. 示范：法务合同高风险条款助手（纲要）

**澄清**：律师初审；漏检成本高；合同不出域；可 HITL。  

**范围**：仅 NDA/保密与赔偿责任两类；不做自动改写对外发送。  

**架构**：本地/私有模型或私有链路 → 解析 PDF → 条款切片 → 检索模板与历史批注 → 模型标疑似高风险并引用 → 律师确认写回 CLM。  

**Eval**：200 段标注；漏检率优先；每周错误本。  

**Rollout**：影子标注 → 律师收件箱建议 → 再谈是否扩大条款类。  

**风险**：解析烂表、模板版本、律师不信任 → 用可解释引用与速度赢采用。

## 5. 加分句（自然使用）

- 「错误代价决定自动化级别。」  
- 「权限在检索层强制，不靠提示词。」  
- 「没有冻结测试集就不报准确率。」  
- 「成本与 P95 延迟写进设计。」  
- 「可复用的是模式，不是这个客户的 if-else。」  

---

## 6. 减分句

- 「先用 Agent 框架搭起来再说。」  
- 「准确率大概 95%。」（无集无定义）  
- 「安全之后再补。」  
- 「微调一定更好。」  

---

## 7. 练习法

1. 每天一题，计时 15 分钟，只说不写也可  
2. 自己画架构，拍照复盘缺了哪层  
3. 对同学追问：权限？eval？成本？失败？
