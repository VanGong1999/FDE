# AI 初创公司面试指南（AI Startups）

> 原文来源：The Forward Deployed —— https://www.theforwarddeployed.io/。本篇为其「AI Startups（AI 初创公司）」章节的完整中文翻译整理，公司名、产品名与专有名词保留英文。本篇是「公司差异与薪酬.md」中「初创公司 —— 考察全面性」一节的延伸与详细展开，建议先读那篇建立整体认知，再回到本篇深入备考。

## 这个角色通常意味着什么

在初创公司，「forward deployed engineer」通常意味着：派到客户那里去的工程师，同时几乎什么都得干。没有独立的职级阶梯，也没有招牌环节（signature round）。《The Pragmatic Engineer》对这个角色的描述——亲自动手、在真实的模糊性下直接于客户基础设施上写代码——是最接近的稳定参照点（参见 The Pragmatic Engineer 论 forward deployed engineers）。

## AI 初创公司正在收敛的模式

没有两家初创公司跑完全相同的流程，但 AI 初创公司的 FDE 面试有一个可辨认的形态：通常在三到四周内有五到八个触点，比 Palantir 或前沿实验室更快。

| 阶段 | 形式 | 考察什么 |
|------|------|----------|
| Recruiter 电话初筛 | 约 30 分钟电话 | 动机、岗位匹配、为什么做 FDE |
| 实际编码 | 约 60 分钟或 take-home | 在宽松规格下的真实工程 |
| System design | 约 60 分钟 | 一个真实的部署，端到端 |
| 客户对话模拟 | Roleplay | Discovery、约束、沟通 |
| 创始人或招聘经理轮 | 对话 | Ownership、产品感、动机 |

Take-home（在出现的地方）跑几个小时，镜像真实的产出工作。现在有足够多的 AI 初创公司在招这个岗位，因此这个形态在整个领域都清晰可见，尽管任何一家公司都会有所不同。

## 逐阶段拆解

### Recruiter 电话初筛（约 30 分钟）

动机与岗位匹配，节奏很快。唯一可靠重要的一件事：你有一个想做 forward-deployed 工作的具体理由，并且你乐意做那个驻场、同时还要什么都干的工程师。

代表性提问：为什么做 forward-deployed engineering，以及为什么在这个阶段选这家初创公司？给我讲讲你端到端负责过的某件事。你能接受在客户现场，同时还要负责构建吗？

### Take-home 构建，现场展示并延伸

大多数 AI 初创公司偏爱一个镜像真实产出工作的 take-home，通常是一个 agent 或功能，你对着提供的 API key 去构建，然后在层层「为什么」追问下现场展示并延伸。领先的 agent 公司现在跑一个 AI-native 版本：你用自己的 AI 工具花几个小时规划并构建（Sierra）。有些公司仍然在前期用 LeetCode 或 CodeSignal 的筛选做门槛，少数公司则改为要求一份关于你最杰出工作的书面陈述（候选者报告）。在编码环节上打磨构建。

### Production-AI 技术轮

这不是一个固定的 system design 轮，而是根据公司呈现两种形态：在产出型初创公司，是一个 agent 构建或延伸练习；在企业基础设施型初创公司，是为你的架构辩护，并调试一个模糊的、假设驱动的问题。无论哪种，你通常独自承担生产权衡——成本、延迟和上线（rollout），所以在 system design 案例里设计一个自带预算的东西。

### 客户对话模拟（决定 offer 的一轮）

这一轮最能预测你是否能在客户内部交付价值，也是许多技术很强的候选人掉队的地方。有时是一个独立的 roleplay，常常嵌入另一轮，但信号是一样的：你处理一个含糊、有时充满敌意的客户场景，挖出真正的约束，并在压力下保持冷静。下面的 discovery 框架就是全部。在客户模拟练习上反复演练它。

### 过往项目深挖

在初创公司很常见：面试官深挖一个你个人负责过的项目，直到触及你理解的边界。挑一个你真正构建过、能辩护到最后一个决定的东西，并在边界处如实说明。

### 创始人或招聘经理轮

Ownership、产品感和动机，通常有创始人参与。它奖励这样的证据：你能端到端地扛下一个问题，并把你学到的东西反馈回产品。

代表性提问：给我讲讲在极度模糊下交付上线。在我们的第一个客户身上，你前两周会做什么？为什么是我们、在这个阶段？在价值观和招聘经理练习上准备这些。

## 答题框架

### 为单个客户界定第一片

1) 搞清楚那个最痛的 workflow，以及客户被考核的结果。2) 砍到你能本周交付、且能推动它的最窄的一片。3) 点明你独自承担的约束：成本、延迟和客户的数据边界。4) 尽快把某个东西放到真实用户面前，并衡量它是否管用。5) 把你学到的东西反馈回产品。在初创公司你拥有整条弧线，所以要展示你能压缩它。

### 主导 discovery 对话

1) 问这个业务被考核的结果是什么。2) 问数据存在哪里、什么不能离开。3) 问他们试过什么、为什么没成。4) 用他们自己的话把真正的约束复述回去。5) 只有到这时才提出一个窄窄的第一片。这是决定 offer 的一轮；跳向一个方案就会输掉它。

### 在压力下排查生产故障

当集成在客户环境里崩了：1) 先稳住，即使用临时手段也要先止血。2) 在客户开口之前告诉他们你知道什么、正在做什么。3) 依据 blast radius 和你的把握，在 hotfix 和 rollback 之间做决定，并说明为什么。4) 一旦平静下来，追根究底，并加上本可以抓住它的检查。保持冷静并沟通，和修复本身一样被计分。

### 回答「为什么做 FDE」

这是初创公司里最重要的一道答案。把面向客户的技术工作和你自己的动机连起来：在真实客户内部负责一个结果、在模糊下交付、端到端地扛下一个问题，包括那些不是你的错的部分。泛泛的「我喜欢多样性」会失败；一个具体、诚实的理由会赢。

## 一个完整范例

比任何其他问题都更能决定初创公司 offer 的问题：「为什么 forward-deployed？」

Weak（弱）。「我喜欢多样性，而且我是 full-stack，所以什么都能做一点。」这可能是真的，但它没说明你是否会在一家难搞的客户内部负责一个结果。

Strong（强）。「我喜欢在真实客户内部端到端地负责一个问题，包括那些不是我的错的部分。在我上一个项目里，我和客户坐在一起，发现阻塞点不是模型，而是一个没人信任的数据导出；我先把它修好，然后交付了一个他们下一周就用上的东西。那个循环——从 discovery 到东西真正落到某人手里——正是我想要的工作，而初创公司是我能最大程度拥有它的地方。」你把角色和你做过的一件具体的事、一个具体的动机绑在了一起。

## Take-home 备考

如果流程里有 take-home，把它当作这份工作的缩影。在真实数据上构建一个能跑通的小切片，并让它以能体现 ownership 的方式具备「production-shaped」的形态：一句关于「哪个指标说明它管用」的说明、真实体量下的成本和延迟、客户的数据边界在哪里，以及一段关于你接下来会交付什么、砍掉了什么的短文。像对客户那样展示它：先讲问题和结果，再讲决策。它的评分标准是你能否界定并交付，而非打磨得多精致。

## 面试官在打什么分

AI 初创公司的 FDE 面试流程打一套一致的分数。客户流利度与共情：向非技术干系人解释一个系统。彻底的 ownership：端到端扛下一个问题，包括不是你的错的部分。模糊下的拆解：把模糊的简报变成计划。产品感：把部署信号反馈回产品。压力下的沟通：当客户的 VP 在一个周五情绪激动时保持冷静。以及一个想做 forward-deployed 工作的具体理由。标杆是在所有这些维度上的全面性（versatility），而非任何单一维度的深度。

## 练习提示

面向初创公司往往考察的「全面性」标杆的代表性提示。演练拥有整条弧线，因为在这里这就是无结构的考察点。

- 一个单一客户就是你整个季度的路线图。他们描述了一个你从未见过的 workflow 里的模糊痛点。从第一次对话到交付第一片：你学到了什么、砍掉了什么、先放到真实用户面前的是什么。
- 你是现场唯一的工程师，你交付的集成在一个周五下午崩在了客户环境里。讲讲你如何排查、怎么跟客户说，以及你如何在 hotfix 和 rollback 之间做决定。

## 如何调研具体公司

回报最高的备考是读真实的职位发布，并依据它要求你负责什么来判断这个岗位，而不是看头衔。Companies Hiring FDEs 有你在备考前要确认什么的清单；Company Differences 提供背景。

## 两周备考计划

没有具体公司的流程可以收窄，广度就是备考本身。第一周：在混乱、规格多变的题目上打磨编码，练习对模糊客户简报的拆解，并跑一个自带成本和延迟的 AI system design 案例。

第二周：演练 discovery 对话（客户模拟），准备一个端到端的 ownership 故事和一个具体的「为什么 FDE」答案（价值观练习），并确保你的证据展示了一个你从 discovery 到 rollout 都负责的结果。然后从职位发布去调研具体公司。

## 常见问题（FAQ）

### 初创公司 forward deployed engineer 的面试流程是什么？

没有标准流程，但 AI 初创公司的 FDE 面试大致收敛到三到四周内的五到八个触点：recruiter 电话初筛、实际编码或 take-home、system design 轮、客户对话模拟，以及创始人或招聘经理轮。任何一家初创公司都会不同，所以问问你的 recruiter 它的流程包含什么，并对照职位发布里的职责去备考。

### 初创公司 FDE 面试会出现哪些样例题？

各轮的代表性题目：「为什么 forward-deployed，以及为什么在这个阶段选我们？」；一个宽松规格的编码任务或简短 take-home；在 roleplay 里，你在提出方案前必须问客户的 discovery 问题；以及创始人轮的提示，如「在我们的第一个客户身上，你前两周会做什么？」上面的「答题框架」一节分别对每个进行了结构化。

### 初创公司 FDE 面试中哪一轮最重要？

客户对话或 discovery 轮：它最能预测你是否会在客户内部交付价值，也是许多强编码者掉队的地方。紧随其后的是对「为什么做 forward-deployed 工作」的一个具体回答，并连到你自己的动机。在客户模拟和价值观练习上分别演练这两项。

### 公开信息这么少，我该怎么备考初创公司 FDE 岗位？

按广度备考。初创公司的标杆是在更少结构下的全面性与 ownership，所以打磨编码、拆解、客户模拟和 AI system design，并准备一个你端到端负责过结果的项目。然后从职位发布去调研具体公司，而不是一份泛泛的指南。
