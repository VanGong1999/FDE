# Take-home 与演示

部分 AI 公司（公开报道中 OpenAI FDE 等）会用 **Take-home + 录屏/现场讲演** 筛人。评分常偏「生产形」而非炫技。

---

## 1. 他们在找什么

综合公开指导的共性维度：

| 维度 | 强 | 弱 |
|------|----|----|
| 问题定义 | README 写清用户与目标 | 只有代码无语境 |
| 功能完整度 | 主路径可跑 | 半成品堆库 |
| Eval | 有测试集与结果解读 | 「我觉得还行」 |
| 安全边界 | 权限/密钥/数据说明 | 明文 key、无边界 |
| 成本与延迟 | 有测量或估算 | 无视 |
| Rollout | 分阶段计划 | 「直接上生产」 |
| 演示 | 像对客户讲 | 像对程序员炫实现 |

---

## 2. 推荐作品形态（选一做透）

1. **带权限说明的文档问答 RAG**（本地文件夹或演示 ACL）  
2. **带 HITL 的小 Agent**（如草稿工单，确认后提交）  
3. **Eval 工具**：对某任务跑回归并产出失败报告  

宁小而完整，不大而空。

---

## 3. 交付物清单

- [ ] 可运行说明（5 分钟内跑起）  
- [ ] `.env.example`，无真实密钥  
- [ ] 架构短文（1 页）  
- [ ] Eval：数据集路径 + 指标 + 已知失败  
- [ ] 安全与限制章节  
- [ ] 成本/延迟笔记  
- [ ] Rollout 建议（影子→试点→扩大）  
- [ ] 演示脚本（见下）  

---

## 4. 演示脚本（5–8 分钟）

1. **场景与用户**（30s）  
2. **约束**（数据、风险）（30s）  
3. **现场成功路径**（2–3 min）  
4. **故意展示一个失败/拒答**（1 min）——加分  
5. **Eval 结果**（1 min）  
6. **若上线：下一步与风险**（1 min）  
7. **收尾：你要的反馈问题**（30s）  

语速稳；不要读代码。假设观众是客户技术负责人。

---

## 5. 录屏注意

- 分辨率与麦克风清晰  
- 提前打开该开的窗口  
- 失败要提前演练，别现场抓瞎  
- 控制在要求时长内  

深挖轮常会就演示追问：每个决策都要能辩护。

---

## 6. 时间盒（以 ~5 小时作业为例）

| 小时 | 焦点 |
|------|------|
| 0–0.5 | 写问题陈述与非目标 |
| 0.5–2.5 | 主路径实现 |
| 2.5–3.5 | Eval + 失败例 |
| 3.5–4.5 | 安全、README、rollout |
| 4.5–5 | 演练演示 |

超时就砍功能，不砍 Eval 与 README。

---

## 7. 常见翻车

- 交了笔记本才能跑的路径依赖  
- 把 API key 提交到 Git  
- 演示只挑甜例  
- 无 license/无引用第三方  

---

## 8. 读完马上做

- [ ] 选定作品形态并开仓库  
- [ ] 先写 README 的问题陈述再写代码  
- [ ] 按脚本录一版私密演示自评
