# Take-home 与演示

部分 AI 公司（公开报道中 OpenAI FDE 等）会用 **Take-home + 录屏/现场讲演** 筛人。评分常偏「生产形」而非炫技。

相关：[OpenAI 精读](../07-外文精读/04-OpenAI-FDE面试指南.md)、[评测](../03-AI落地/评测Eval与Guardrails.md)、[零基础作品周](../05-能力补强/零基础编程补课地图.md) 第 4 周可作雏形。

---

## 1. 他们在找什么

| 维度 | 强 | 弱 |
|------|----|----|
| 问题定义 | README 写清用户与目标 | 只有代码无语境 |
| 功能完整度 | 主路径可跑 | 半成品堆库 |
| Eval | 有测试集与结果解读 | 「我觉得还行」 |
| 安全边界 | 权限/密钥/数据说明 | 明文 key、无边界 |
| 成本与延迟 | 有测量或估算 | 无视 |
| Rollout | 分阶段计划 | 「直接上生产」 |
| 演示 | 像对客户讲 | 像对程序员炫实现 |
| 决策辩护 | 说得出弃选方案 | 「因为教程这样写」 |

---

## 2. 推荐作品形态（选一做透）

1. **带权限说明的文档问答 RAG**（本地文件夹或演示 ACL）  
2. **带 HITL 的小 Agent**（草稿工单，确认后提交）  
3. **Eval 工具**：对任务跑回归并产出失败报告  

宁小而完整，不大而空。加分项：故意展示拒答/失败 + 如何发现。

---

## 3. README 建议目录

```text
# 项目名
## 用户与问题
## 非目标
## 快速开始
## 架构（含权限点）
## Eval（如何跑、分数、已知失败）
## 安全与数据边界
## 成本与延迟
## Rollout 建议
## 演示脚本时间码
```

## 4. 交付物清单

- [ ] 5 分钟内可跑起（容器或一键脚本更佳）  
- [ ] `.env.example`，无真实密钥；`.gitignore` 正确  
- [ ] 架构短文（1 页）  
- [ ] Eval：数据路径 + 指标 + 已知失败  
- [ ] 安全与限制章节  
- [ ] 成本/延迟笔记（哪怕是估算表）  
- [ ] Rollout：影子 → 试点 → 扩大  
- [ ] 演示脚本 + 已私人预录一版  

---

## 5. 演示脚本（5–8 分钟）

| 段 | 时长 | 内容 |
|----|------|------|
| 1 | 30s | 场景与用户 |
| 2 | 30s | 约束（数据、风险） |
| 3 | 2–3min | 成功主路径（操作，不念代码） |
| 4 | 1min | **故意失败/拒答** |
| 5 | 1min | Eval 结果 |
| 6 | 1min | 若上线：下一步与风险 |
| 7 | 30s | 你想听的反馈问题 |

假设观众是**客户技术负责人**，不是竞赛评委。

---

## 6. 录屏与现场

- 分辨率、麦克风、字体放大  
- 提前打开窗口；关掉通知  
- 失败路径演练 ≥2 次  
- 控制时长；超时先砍功能演示，不砍 Eval  
- 深挖轮会追问每个决策——列「弃选方案」清单备用  

---

## 7. 时间盒（~5 小时作业）

| 小时 | 焦点 |
|------|------|
| 0–0.5 | 问题陈述与非目标 |
| 0.5–2.5 | 主路径 |
| 2.5–3.5 | Eval + 失败例 |
| 3.5–4.5 | 安全、README、rollout |
| 4.5–5 | 演练演示 |

超时砍功能，**不砍 Eval 与 README**。

若你有更长时间（周末项目）：补权限演示用户 A/B、补简单观测日志。

---

## 8. 常见翻车与自检

| 翻车 | 自检 |
|------|------|
| 只有你笔记本能跑 | 换一台机器按 README 走一遍 |
| Key 进 Git | `git log -p` 搜 key；轮换密钥 |
| 只挑甜例 | 脚本里固定播失败例 |
| 无许可证/乱贴代码 | 注明依赖与许可 |
| 指标无定义 | 写清 n=多少、量规是什么 |

## 9. 答辩高频追问（准备 30 秒答）

1. 为什么不用微调？  
2. 权限怎么保证？  
3. 如何知道没幻觉？  
4. 成本到 10× 流量怎么办？  
5. 客户说下周全自动，你怎么答？

## 10. 周末级端到端练习：电商站挂 AI 助手

> 整理自公开教程 [Juice Shop + AI 助手](https://www.youtube.com/watch?v=miHREcaScRY)（Abhishek）。用 OWASP Juice Shop 等开源店，目标是**可演示的 FDE 生命周期**，不是生产方案。

### 建议范围（对照评分表）

| 项 | 做 | 刻意不做（非目标） |
|----|----|--------------------|
| 需求 | 可答：价格/库存/评价；不可答：未来价、内部反馈 | 全自动下单/退款 |
| 实现 | Python + FastAPI `/ask` + 护栏 | 重写整个电商后端 |
| RAG | 产品文档 → embeddings → Chroma（或同类） | 一上来微调 |
| 前端 | 右下角小部件调 API | 像素级重美工 |
| 部署 | Docker Compose 本地四件套 | 一上来 K8s 多集群 |
| 证明 | README + 3 个成功例 + 1 个拒答例 + 成本记录 | 「感觉挺准」 |

### 生命周期检查（可当 Take-home README 目录）

1. 需求收集（1–2 天盒）  
2. 模型/工具选型（可路由省成本）  
3. 助手实现 + 护栏  
4. RAG（通常最难）  
5. 前端集成  
6. Docker 本地验收  
7. 可观测性预留（日志字段设计即可）  
8. 交接文档  

**提醒：** FDE ≠ 全栈炫技；语言无关、API 解耦即可。密钥进 Vault/Secret Manager 的叙述写进 README「生产下一步」。
