# 公司差异与薪酬

> 原文来源：The Forward Deployed —— https://www.theforwarddeployed.io/。本篇为其「Company Differences（公司差异）」章节的完整中文翻译整理，公司名、产品名保留英文。

「Forward Deployed Engineer（FDE）」在不同的公司含义并不相同。不变的一点是：你对一个客户结果负责，并编写代码去交付它。但各家公司招什么样的人、要求多高的资历、强调什么，差异大到你必须在备考之前先读具体的职位描述。本页根据一手资料梳理这些差异，并对公开数据稀缺之处如实说明。

## 关于数字，以及它们的时效

资历要求引用自各公司自己的招聘启事；薪酬数据来自 Levels.fyi 的自报数据。本页所有数字都随文标注了来源与截至日期（薪酬数字截至 2026 年 7 月；招聘启事于 2026 年初核对）。请把它们当作方向性参考，并重新核对最新招聘启事，因为这个领域的职级区间与头衔变动很快。

下面每一家雇主也都有一份专门的面试指南，把公开所知的面试流程对应到该做的练习：Palantir、OpenAI、Anthropic、Google Cloud，以及初创公司。打开与你目标公司对应的那一份。

## 这个角色，以及它旁边的角色

在谈各公司差异之前，先把那个容易把人绊倒的区分讲清楚。《The Pragmatic Engineer》把它画得很干净。解决方案架构师（solutions architect）是咨询性质的：他们很少在客户的基础设施上写代码。而 Forward Deployed Engineer 是亲自动手的：他们直接在客户基础设施上写代码，并且要比传统的云解决方案架构师面对更多模糊性。如果一份招聘启事其实是披着 FDE 外衣的售前工程或咨询岗位，破绽就是它从不要求你交付上线（ship）。

## Palantir —— 开创者

Palantir 发明了 forward-deployed 模式（即 FDSE / FDE 头衔），并且至今仍是资料最充分的面试流程（整套 Interview Method 都依托于它）。有两点让它与众不同：

- 它招聘的资历区间最宽。不同于前沿实验室（frontier labs），Palantir 的 forward-deployed 团队横跨各个经验层次招聘，据《The Pragmatic Engineer》，甚至包括大学毕业后只有一年工作经验的工程师。如果你处于职业生涯早期，这是最敞开的一扇门。
- 它的面试流程以「问题拆解（decomposition）」为核心，而非算法。它的招牌环节是开放式的「问题拆解」，仅靠刷算法是过不了这一关的。

薪酬（Levels.fyi，自报数据，截至 2026 年 7 月）：Forward Deployed Software Engineer 这一头衔在美国的中位数总薪酬约为 20.1 万美元，区间大致在 15.9 万至 32.5 万美元之间。自报数据，仅供参考方向。

## OpenAI —— 资历要求最深

OpenAI 的 FDE 招聘启事在各大公司中要求的经验最多，并把该角色定位为端到端的 ownership（端到端负责）。

- 资历要求：「5 年以上」工程或技术部署经验，且需包含面向客户的工作。
- 他们强调什么：负责整条链路（owning the whole arc）。该角色被描述为「负责 discovery、技术范围界定（technical scoping）、系统设计、构建与生产上线」，并且在「进展依赖代码时」要「直接动手写代码」。他们想要的是那种「在快速变动或模糊的环境中界定并交付过复杂系统」的人。
- 面试流程线索：一则第一手叙述描述了一个 API 的 take-home 作业，随后是一次 walkthrough（仅此一则第一人称叙述）。请对照最新招聘启事核实，因为关于前沿实验室面试流程的独立细节很少。

## Anthropic —— MCP 原生、深度嵌入客户

Anthropic 的 Applied AI / FDE 角色在资历上略低于 OpenAI，并且明显受到其自身协议栈的塑造。

- 资历要求：技术性、面向客户岗位「3 年以上」经验，或具备咨询经验的软件工程师。
- 他们强调什么：要「直接与我们的战略级客户」深度嵌入（embedding），并在其生态中交付生产级成果。招聘启事点名要交付用于生产的「MCP 服务器、子代理（sub-agents）与 agent 技能（agent skills）」，并要求「高度自主（high agency）以及驾驭模糊性的能力」。如果你目标是 Anthropic，掌握 Model Context Protocol（模型上下文协议）几乎就是入场门槛。

## Google Cloud —— 分级职级阶梯

Google 于 2026 年开始招聘 FDE，据《The Pragmatic Engineer》解读其招聘启事，大致是四分之一写代码、一半做集成与「管道疏通（plumbing）」、四分之一开会和安抚客户，其中「创始人思维（founder's mindset）」翻译过来就是「没人会给你规格说明，范围蔓延（scope creep）是你自己的问题」。同一个头衔横跨多个职级与薪酬区间，所以要以具体招聘启事中的「工作年限」一行为准。关于实际运作细节，见《The Job, Week to Week》。

## 初创公司 —— 考察全面性

在初创公司，「forward deployed engineer」通常意味着「我们派到客户那里的工程师，同时什么都得干」。没有独立的职级阶梯，也没有成文的面试流程；考察的是在更少结构约束下的全面性（versatility）与 ownership。公开可引用的具体信息基本没有，所以要依据其职位描述实际要求什么来判断任何一个初创公司的 FDE 岗位；光看头衔说明不了什么。

## 这对你的备考意味着什么

- 职业生涯早期：Palantir 的宽资历区间是最容易进入的入口，其「拆解优先」的面试流程也是资料最充分、最适合备考的。
- 中高级、有生产「伤疤」经验者：前沿实验室（OpenAI 5+、Anthropic 3+）看重可展示的端到端 ownership，并且越来越看重对其自身技术栈的熟练度（Anthropic 的 MCP）。
- 对所有人：真正的分水岭是「证据门槛（evidence bar）」。资历那一行只是让你被看到，交付上线的生产级工作才是让你被录用的东西。

## 延伸：对这些信息保持审慎

这个领域重新定价和改头衔的速度很快。薪酬区间，甚至哪些公司设有独立的 FDE 团队，一年之内就会变化。用本页去理解差异的「形状」；在谈判中引用具体数字之前，务必对照最新招聘启事与 Levels.fyi 核实。
