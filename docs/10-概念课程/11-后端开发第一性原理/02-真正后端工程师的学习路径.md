# 02 · 真正后端工程师的学习路径

一句话直觉：先把「故事与哲学」（语言无关的原则）吃透，再进具体语言实现，最后用生产级项目把一切拼起来——这样你才是后端工程师，而不是「某个框架的教程跟随者」。

## 本课要解决什么问题

- 开刷「干货」之前，先对齐**期望**：这套 playlist 到底教什么、怎么学、学完能达到什么水平。
- 避免一上来就扎进语法与样板代码，却看不见生产级后端的大图与组件协作。
- 说明课程分三阶段，以及本 playlist 与后续 Node.js / Go 实现课、生产项目课的关系。

## 核心概念详解

### 本 playlist 要讲的是什么

讲师明确：这套内容讲的是**后端工程的故事（story）与哲学（philosophy）**——

- 背后的大问题（big questions）
- 组件之间如何协作
- 机器与系统如何配合

目标：让你看见**生产级后端的大图**，并真正理解日常被语言、运行时、框架、库**抽象掉**的那些概念。

这是成为**具备语言无关（language-agnostic）技能**的后端工程师的**第一步**：技能超越你每天用的某一个框架或库。

### 三阶段学习路径

#### 阶段一：故事与哲学（本 playlist）

- 建立共同模式：几乎所有后端应用背后的重复结构。
- 理解原则如何「连点成线」。
- **不先绑死语言**，先看清领域地图。

#### 阶段二：实现（Implementation）——独立 playlist

当基础清晰、能看到共性模式后，才谈实现：原则如何在真实代码中落地。

- 需要选择**语言与生态**。
- 讲师计划出两套：**Node.js** 与 **Go**（其日常工作栈）。
- 本 playlist 中的多数原则视频，会在下一 playlist 有**对应的语言实现深潜**。

示例：原则课讲数据库、驱动、迁移等；实现课会分别深潜：

- Node：如 `postgres.js` 驱动 + PostgreSQL
- Go：如 `pgx` 驱动 + PostgreSQL  
并覆盖该主题周边的全部日常概念。

#### 阶段三：生产级项目（Production-level projects）

- 把概念、语言深潜、哲学全部合在一起。
- **端到端**做符合工业标准与最佳实践的项目。
- 多个可跟随练习的项目。

### 学完应达到的能力

若完整走完并内化、跟完项目，应能自信称为后端工程师，并构建：

- 真实系统（real systems）
- 可从 0 用户扩到百万用户的系统
- 可长期维护的系统

### 期望对齐一句话

本阶段 = **地图 + 原则**；下一阶段 = **用选定语言把每块积木写出来**；最后阶段 = **按生产标准把系统盖起来**。

## 后端规则与最佳实践（Checklist）

- [ ] 先学「为什么、是什么、如何协作」，再学「用哪门语言怎么写」。
- [ ] 把本课当作**原则索引**：后续每条原则都预期有 Node/Go 实现对照。
- [ ] 实现阶段按**原则拆模块**深潜（库、驱动、生态惯例），而不是只抄一个大而全教程。
- [ ] 生产项目阶段刻意练：标准、最佳实践、可维护与可扩展，而不只是「能跑」。
- [ ] 衡量标准：能否构建从 0 扩到大规模、且别人能长期维护的系统——而不只是完成教程。

## 常见坑与反模式

- **跳过哲学直接抄框架**：能出 Demo，换栈或进陌生仓库就迷路。
- **把本课当成「不用写代码所以可略过」**：本课正是为后面实现与项目铺心智模型。
- **只追一门语言的完整项目视频**：资源质量参差；没有原则地图时，稀缺语言（如 Rust）更容易卡在「会语法不会做生产后端」。
- **期望本 playlist 就教到某一框架 API**：明确不在本阶段；实现在下一 playlist。
