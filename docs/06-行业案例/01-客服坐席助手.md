# 案例：客服坐席助手（非全自动）

> 状态：可发布  
> 类型：合成教学案例（脱敏行业共性，非真实客户细节）  
> 主模式：RAG + 坐席助手 + 影子/确认模式  

## 1. 背景

- **组织类型**：中大型消费品牌，日均工单数千，呼叫中心与在线客服并存  
- **业务痛点**：新人培养周期长；政策/活动规则多变；一次解决率（FCR）不稳；高峰排队  
- **推动力**：管理层看了竞品「AI 客服」Demo，要求「三个月降人工」  

## 2. Discover

- **真实用户**：一线坐席（日用）、质检、培训师；赞助人是客服 VP  
- **指标**：FCR、AHT（处理时长）、升级率、CSAT；**不是**「机器人回复条数」  
- **约束**：工单系统（如 Zendesk/自研）必须写回；部分客户数据不可出域讨论中；对外自动发送需法务批准  
- **问题陈述**：一线坐席在处理咨询时，需要快速得到**可引用的政策答案与建议话术**，今天靠老人带教与搜索内网，痛点是找不全/找得慢；成功时新人达到合格 FCR 的周期缩短，且差错率不高于基线  
- **非目标**：第一期不做全自动对外回复、不做语音全接管  
- **硬点**：① 活动规则版本与生效时间；② 答错导致的补偿/退款风险；③ 坐席不信任则零采用  

## 3. Design

- **主模式**：知识库 RAG + 坐席侧「建议面板」；默认**不自动发送**给客户  
- **架构要点**：  
  - 工单上下文（摘要/标签）→ 鉴权 → 混合检索（政策/FAQ/历史优质工单）→ 生成建议 + 强制引用 → 坐席一键采纳/编辑后发送  
  - 高危意图（退款、销户、投诉升级）路由到固定话术模板 + 人工确认清单  
- **试点切片**：在线文字渠道 × 一个品类（如会员与积分）× 2 个班组 × 4 周  
- **Eval 通过线**：冻结 150 题；引用正确率 ≥ 85%；应拒答/应升级命中 ≥ 95%；试点期建议采纳率 ≥ 30%  

## 4. Deploy

- **集成**：嵌入坐席工作台侧栏；写回「AI 建议是否采纳」字段  
- **HITL**：默认全部人工发送；第二阶段仅对「低危、高置信、模板类」开放半自动  
- **培训**：30 分钟上手 + 「如何报告错误建议」；质检把 AI 相关差错纳入抽检  
- **事故处理预案**：错误补偿建议被发送 → 即时停用该意图路由 → 复盘进黄金集  

## 5. Review（合成结果）

- **结果**：采纳率 41%；该品类新人达标周期 6 周→4 周；AHT 微降；发现 2 次过期活动页导致错误建议（已加生效时间过滤）  
- **学习**：管理层原要的「全自动」在无评测时不可接受；**坐席助手**更能过安全与采用  
- **可复用模式**：影子/确认 → 意图分级 → 引用强制 → 采纳率作主指标  
- **产品反馈**：需要「活动生效窗口」作为一等元数据；工作台 SDK  
- **下一步**：扩展第二品类；仍不对开放域闲聊自动发送
