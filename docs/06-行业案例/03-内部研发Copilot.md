# 案例：内部研发 Copilot

> 状态：可发布  
> 类型：合成教学案例  
> 主模式：代码库 RAG + IDE/CLI 助手；强保密  

## 1. 背景

- **组织**：中型 SaaS，微服务多、文档落后、onboarding 慢  
- **痛点**：新人找入口难；重复造轮；Code Review 解释成本高  
- **敏感**：源代码与客户配置不可进入未审批的公有模型训练/日志  

## 2. Discover

- **用户**：后端/全栈工程师；平台组关心密钥与仓库权限  
- **指标**：首个有效 PR 时间、重复问题次数、自评「找代码时间」  
- **约束**：代码仓库按团队 ACL；生产密钥禁止进提示；部分客户定制分支隔离  
- **问题陈述**：工程师在理解与修改陌生服务时需要**基于本仓库证据**的解释与草稿；成功时 onboarding 周期缩短且无密钥泄漏事件  
- **非目标**：不做自动合并 PR；不做跨客户代码共享检索  
- **硬点**：仓库级权限；提示/日志中的密钥扫描；幻觉 API  

## 3. Design

- **主模式**：仓库索引 RAG + 补全/问答；可选「测试草稿」生成  
- **架构**：  
  - 企业版模型或私有网关；关闭训练；日志脱敏  
  - 按用户 Git 权限同步可检索仓库集合  
  - 回答要求指向文件路径与符号；未知则说「仓库中未找到」  
- **试点**：2 个中等复杂度服务 + 20 名工程师 × 6 周  
- **Eval**：50 个「如何改 X」任务；正确路径命中率；密钥泄漏红队用例 0  

## 4. Deploy

- **入口**：IDE 插件 / 内部聊天；与现有文档站互链  
- **护栏**：提交前密钥正则；禁止粘贴 `.env`  
- **变更**：提示词与索引版本化；周发布  
- **采用**：Lunch-and-learn；收集「最有用/最胡说」案例进评测集  

## 5. Review

- **结果**：新人首 PR 中位时间下降约 20%；最大价值在「解释遗留模块」而非写新功能；幻觉集中在过时注释  
- **学习**：Copilot 不能替代架构评审；文档债仍要还  
- **可复用**：权限同步索引、路径引用、密钥红队  
- **下一步**：加「生成测试」工作流；仍人工合并
