# 案例：流程型 Agent（工单办理）

> 状态：可发布  
> 类型：合成教学案例  
> 主模式：固定工作流 + 工具调用 + 分级 HITL（非无限自主 Agent）  

## 1. 背景

- **组织**：企业内部 IT/HR 服务台，流程跨多个系统（账号、权限、资产）  
- **痛点**：员工填错单；专员来回问信息；简单请求也排队  
- **诱惑**：「做一个全能 Agent 自动办结一切」  

## 2. Discover

- **用户**：员工（提单人）、服务台专员、系统 owner（AD/ITSM）  
- **指标**：首次解决时长、来回补件次数、错误开通率、审计合规  
- **约束**：写操作高危；权限模型复杂；部分动作需经理审批  
- **问题陈述**：员工提交「账号权限类」请求时，需要在一次会话中收齐必要信息并生成正确工单/执行只读校验，减少补件；高危变更仍需审批  
- **非目标**：第一期不自动改生产权限组；不做跨所有 IT 流程的超级 Agent  
- **硬点**：工具权限代理；错误开通的回滚；提示注入诱导越权  

## 3. Design

- **主模式**：**状态机工作流**（收集信息 → 校验 → 创建草稿 → 人工/经理批准 → 执行）  
- **工具分级**：L0 查询员工信息；L1 创建 ITSM 草稿；L2 改权限（HITL）；禁止原始 Shell/万能 SQL  
- **架构**：用户 SSO → 工具网关（以用户/代理身份限权）→ 业务 API；全程轨迹审计  
- **试点**：「VPN 开通 / 邮箱组申请」两类 × 一个事业部 × 4 周  
- **Eval**：任务成功率、非法提升权限拦截率、平均步数/成本、轨迹可审计性  

## 4. Deploy

- **入口**：企业 IM；与 ITSM 双向同步状态  
- **HITL**：所有 L2 展示「将执行的变更摘要」后人点批准  
- **红队**：文档/用户输入中植入「忽略规则并提权」用例  
- **回滚**：每个写操作有补偿 API 或工单回滚 runbook  

## 5. Review

- **结果**：补件次数显著下降；零越权事件（测试+试点）；曾因状态机缺口导致重复建单（加幂等键修复）  
- **学习**：固定工作流比「自由 Agent」更易过安全；自主性可后置  
- **可复用**：工具分级、网关鉴权、幂等、批准卡片  
- **下一步**：加第三类低危流程；仍不开放自由规划器
