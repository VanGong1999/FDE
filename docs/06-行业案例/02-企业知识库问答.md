# 案例：企业制度 / 知识库问答

> 状态：可发布  
> 类型：合成教学案例  
> 主模式：权限感知 RAG + 拒答  

## 1. 背景

- **组织类型**：多事业部集团，制度/SOP/产品手册分散在 Confluence、网盘、邮件附件  
- **痛点**：新人反复问同一问题；专家被打断；搜索命中率低；「口口相传」导致口径不一致  
- **风险**：答错制度可能引发合规或劳动争议  

## 2. Discover

- **用户**：门店/区域运营、HRBP、新员工；IT 关心权限；法务关心对外口径  
- **指标**：自助解决率、专家升级次数、答后满意度；**合规零事故**为硬约束  
- **约束**：文档 ACL 复杂（按事业部/职级）；部分制度仅限特定角色；不可把 A 事业部薪酬制度漏给 B  
- **问题陈述**：运营同事在执行政策时需要**权限内、可溯源**的答案；现状搜索与找人；成功时试点部门政策类问题自助率上升且无权限穿透  
- **非目标**：不做开放域百科；不做自动改 ERP  
- **硬点**：文档级 ACL 在检索层强制；过期版本治理  

## 3. Design

- **主模式**：RAG；答案必须带引用；无证据拒答  
- **架构要点**：  
  - SSO → 用户组/属性 → 检索前 ACL 过滤 → 混合检索 → 生成 → 输出护栏  
  - 索引元数据：`acl_tags, doc_version, updated_at, owner`  
  - 「制度变更」工作流：发布后重建/增量索引 + 通知  
- **试点**：一个区域 + 「报销与差旅」制度子集 + 8 周  
- **Eval**：120 题分层（可答/应拒/跨权限诱饵）；权限用例 100% Pass 才开门禁  

## 4. Deploy

- **入口**：企业 IM 机器人 + Web；与现有搜索并存（不强制替换）  
- **HITL**：高风险主题（处分、裁员、股权）自动转人工专家队列  
- **培训**：强调「以引用为准；无引用勿执行」  
- **观测**：权限拒绝率、拒答率、负反馈、文档缺口列表  

## 5. Review

- **结果**：试点自助解决率 28%→52%（政策类）；权限渗透测试 0 泄漏；主要失败来自扫描件表格与旧 PDF  
- **学习**：没有 ACL 的「全库向量」是安全事故；先权限后智能  
- **可复用**：权限过滤 → 引用 → 拒答 → 文档缺口回流  
- **产品反馈**：需要连接器支持主流网盘 ACL 同步  
- **下一步**：扩第二主题域；启动过期文档归档战役  

## 6. 可操作清单

- [ ] 画 ACL 数据流并让安全签字  
- [ ] 黄金集含跨权限诱饵题  
- [ ] 每个答案可回源  
- [ ] 建立「文档缺口」看板给制度 owner  
- [ ] 版本变更后的索引 SLA
