# 适合谁，不适合谁

转 FDE 成本不低（面试形式特殊、工作节奏前倾、评价标准偏结果）。用下面清单做**诚实自评**，比「跟风投 AI 岗」更重要。

---

## 1. 强匹配信号（越多越好）

- 你做过 **跨团队/有外部用户** 的交付，不只是内部微服务
- 你能忍受 **需求含糊**，并享受把问题变清楚
- 你愿意写文档、做演示、开会——且不认为这是「浪费写代码时间」
- 你对 **现场调试**（权限、数据脏、用户不用）有耐心
- 你关心 **指标与采用**，而不只是技术优雅
- 你能在压力下保持结构化表达（面试 Decomposition 强相关）
- 你对 AI 的态度是「可错系统要工程化」，不是「模型万能」

---

## 2. 风险信号（出现 3 条以上请谨慎）

- 你认为客户沟通「应该完全由 PM/SE 负责」，工程师只管票
- 你强烈排斥出差/驻场/时区会议（而目标公司明确要求）
- 你只想深耕单一技术内核（编译器/内核/训练），讨厌集成脏活
- 你无法接受「这周业务优先级全变了」
- 你抵触被评「项目有没有产生业务结果」
- 你容易在冲突中情绪化升级，而不是写决策备忘录
- 你把 Demo 欢呼当作成功，对评测与安全不感兴趣

风险信号 ≠ 永远不能做，但意味着你要先补行为与动机，或选 **更偏平台的 SWE**。

---

## 3. 自评问卷（1–5 分，1=完全不像我，5=就是我）

| # | 问题 | 分 |
|---|------|----|
| 1 | 我主动澄清过含糊需求，并推动各方同意成功标准 | |
| 2 | 我有过「系统能跑但用户不用」的痛苦经历并解决过 | |
| 3 | 我能把技术限制翻译成业务选项（成本/风险/时间） | |
| 4 | 我在冲突中能坚持范围，而不是默默全接 | |
| 5 | 我愿意为了结果做够用的前端/脚本/脏数据工作 | |
| 6 | 我关注安全与权限，不只是功能 | |
| 7 | 我能接受代码不一定进明星开源，而进客户环境 | |
| 8 | 我愿意把现场模式总结成可复用文档 | |
| 9 | 我对出差/密集会议的耐受度足够目标公司要求 | |
| 10 | 我愿意持续学习模型与评测方法，而不只是调参玄学 | |

**参考解读**：

| 总分 | 建议 |
|------|------|
| 40–50 | 强匹配；直接按转岗路径推进 |
| 30–39 | 可转；针对低分项做 4–8 周刻意练习 |
| 20–29 | 先在当前工作制造「类 FDE」经历，再投 |
| <20 | 优先考虑产品 SWE / 平台，或先做 SE 旁路观察 |

---

## 4. 经历不够时：如何「制造」类 FDE 证据

不必裸辞。在现有工作里主动要这些机会：

1. **内部客户**：把工具送给真实业务团队，跟采用率
2. **端到端**：从需求到上线到培训，写复盘
3. **评测**：任何 AI 功能都加 golden set
4. **权限**：主动做数据分级与审计日志
5. **推回**：邮件记录一次成功的范围控制（可脱敏用于面试）

## 5. 与「解决方案工程师」怎么选

| 你更兴奋的是… | 更合适 |
|---------------|--------|
| 赢单、演示、商务并肩、方案叙事 | SE |
| 长期把系统做进生产、改代码、背结果 | FDE |
| 两者都想 | 看 JD 代码占比；可先 SE 再转 FDE，或反之 |

## 6. 生活与职业约束（单独诚实评估）

| 约束 | 问自己 |
|------|--------|
| 出差/驻场 | 目标公司 JD 是否写明？家庭是否可承受？ |
| 时区 | 能否稳定参加客户早会？ |
| 收入波动 | 部分岗位奖金/签约与项目结果挂钩 |
| 身份与签证 | 跨国客户现场是否可行？ |
| 兴趣曲线 | 12 个月后是否仍愿做集成与采用，而非只想刷模型论文？ |

三项以上「明显冲突」→ 优先平台 SWE / 内部工具，或选出差少的 Applied AI。

## 7. 四条典型画像

| 画像 | 建议 |
|------|------|
| 全栈，做过 ToB 交付，喜欢现场 | 强推；补 Eval/权限深度 |
| 强后端，怕开会 | 先内部客户项目练沟通，再投 |
| 研究型 ML，讨厌脏集成 | 偏研究/平台；或只投研究向 Applied |
| SE，想写更多代码 | 看 JD 代码占比；用 take-home 证明工程力 |

## 8. 「一切都在变成 FDE」时怎么自处

> 补充自 [Sierra 演讲](https://www.youtube.com/watch?v=Byv311hdoHE) 与 [六阶段 FDE 工作流讲解](https://www.youtube.com/watch?v=7jbyXygn9h0)。

- **不要只追头衔**：FDE 可能改名或被吸收；核心能力（理解业务 → 设计 → 构建 → 部署 → 证明 → 扩展）不会消失。
- **不是入门岗**：公开内容常强调需数年真实生产经验；证书不能跳过「脏环境交付」。
- **定价心智**：席位 → 用量 → **结果**；若公司按结果收费，你的工作就是保证结果——这与「只交付功能」人格冲突时要诚实。
- **适合 Factory/Cognition 类的人**：前创始人、系统思考者、能跟各层级对话的技术人；想「替客户做完整专业服务项目」的人，往往与「产品矛尖」定位冲突。
