# 适合谁，不适合谁

转 FDE 成本不低（面试形式特殊、工作节奏前倾、评价标准偏结果）。用下面清单做**诚实自评**，比「跟风投 AI 岗」更重要。

---

## 1. 强匹配信号（越多越好）

- 你做过 **跨团队/有外部用户** 的交付，不只是内部微服务
- 你能忍受 **需求含糊**，并享受把问题变清楚
- 你愿意写文档、做演示、开会——且不认为这是「浪费写代码时间」
- 你对 **现场调试**（权限、数据脏、用户不用）有耐心
- 你关心 **指标与采用**，而不只是技术优雅
- 你能在压力下保持结构化表达（面试 Decomposition 强相关）
- 你对 AI 的态度是「可错系统要工程化」，不是「模型万能」

---

## 2. 风险信号（出现 3 条以上请谨慎）

- 你认为客户沟通「应该完全由 PM/SE 负责」，工程师只管票
- 你强烈排斥出差/驻场/时区会议（而目标公司明确要求）
- 你只想深耕单一技术内核（编译器/内核/训练），讨厌集成脏活
- 你无法接受「这周业务优先级全变了」
- 你抵触被评「项目有没有产生业务结果」
- 你容易在冲突中情绪化升级，而不是写决策备忘录
- 你把 Demo 欢呼当作成功，对评测与安全不感兴趣

风险信号 ≠ 永远不能做，但意味着你要先补行为与动机，或选 **更偏平台的 SWE**。

---

## 3. 自评问卷（1–5 分，1=完全不像我，5=就是我）

| # | 问题 | 分 |
|---|------|----|
| 1 | 我主动澄清过含糊需求，并推动各方同意成功标准 | |
| 2 | 我有过「系统能跑但用户不用」的痛苦经历并解决过 | |
| 3 | 我能把技术限制翻译成业务选项（成本/风险/时间） | |
| 4 | 我在冲突中能坚持范围，而不是默默全接 | |
| 5 | 我愿意为了结果做够用的前端/脚本/脏数据工作 | |
| 6 | 我关注安全与权限，不只是功能 | |
| 7 | 我能接受代码不一定进明星开源，而进客户环境 | |
| 8 | 我愿意把现场模式总结成可复用文档 | |
| 9 | 我对出差/密集会议的耐受度足够目标公司要求 | |
| 10 | 我愿意持续学习模型与评测方法，而不只是调参玄学 | |

**参考解读**：

| 总分 | 建议 |
|------|------|
| 40–50 | 强匹配；直接按转岗路径推进 |
| 30–39 | 可转；针对低分项做 4–8 周刻意练习 |
| 20–29 | 先在当前工作制造「类 FDE」经历，再投 |
| <20 | 优先考虑产品 SWE / 平台，或先做 SE 旁路观察 |

---

## 4. 经历不够时：如何「制造」类 FDE 证据

不必裸辞。在现有工作里主动要这些机会：

1. **内部客户**：把工具送给真实业务团队，跟采用率
2. **端到端**：从需求到上线到培训，写复盘
3. **评测**：任何 AI 功能都加 golden set
4. **权限**：主动做数据分级与审计日志
5. **推回**：邮件记录一次成功的范围控制（可脱敏用于面试）

---

## 5. 与「解决方案工程师」怎么选

| 你更兴奋的是… | 更合适 |
|---------------|--------|
| 赢单、演示、商务并肩、方案叙事 | SE |
| 长期把系统做进生产、改代码、背结果 | FDE |
| 两者都想 | 看 JD 代码占比；可先 SE 再转 FDE，或反之 |
