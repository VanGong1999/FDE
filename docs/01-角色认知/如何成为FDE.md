## 1. 招聘命题（The hiring thesis）

FDE 被雇佣，是为了让一个有价值的系统在客户真实的约束条件下跑起来。因此，你的路线图需要在三列上提供证据：工程深度、客户判断力与生产所有权。课程只能填补词汇缺口；只有真正交付的工作才能填补证据这一列。

---

## 2. 根据你的背景，选择要补的缺口

| 起点 | 可能的优势 | 需要补的缺口 |
|------|------------|--------------|
| 软件工程师 | 生产代码与系统设计 | 客户发现、ROI、模糊范围界定 |
| ML/AI 工程师 | 模型、数据、评测 | 企业集成与干系人所有权 |
| 数据工程师 | 集成、管道、混乱系统 | 产品判断与用户采用 |
| 解决方案工程师 / 架构师 | 客户沟通与架构 | 持续的生产代码所有权 |
| 顾问 | 模糊性、高管沟通、交付 | 动手工程深度 |
| 应届毕业生 | 学习速度与灵活性 | 生产实战经验与可信的客户证据 |

## 3. 四步路线图

### 3.1 清掉工程底线

要能构建并调试一个小型服务、在不熟悉的代码库中工作、设计一个集成、使用 SQL、推理 API 与数据流，并解释可靠性权衡。对于 AI 相关岗位，还要加上检索、工具调用、评测、护栏（guardrails）、可观测性、成本与部署。从 AI Systems 开始。

### 3.2 学习客户生命周期

练习把一个功能请求转化为：一个用户、一个工作流、一个约束、一个可衡量结果、一个首次发布、一个采用计划与一次交接。Customer Outcomes 章节讲授完整弧线。

### 3.3 创造生产证据

给已经在进行中的工作加上一个真实用户、一个真实约束、一个质量指标与一项运营责任。一个被真实团队使用的简单集成，胜过没有人依赖的精致演示。用 Build the Evidence 规划工作并保留决策日志。

### 3.4 为真实面试回路做准备

先清掉编码底线，然后集中精力于拆解、客户推回、陌生代码、生产系统设计与公司特定的动机。Interview Guide 映射了信号，练习章节提供计时训练。

## 4. 当前雇主透露的信号

各雇主要求不一。OpenAI 公开的 FDE 描述强调从发现与范围界定到构建与生产上线的端到端所有权；Anthropic 的 Applied AI 角色强调客户嵌入、模糊性，以及在客户生态中的生产工件。请重新核对最新招聘帖，因为头衔、经验带与团队结构都会变化。OpenAI careers · Anthropic careers。

## 5. 简历法则

以客户或用户的结果开头，点明系统与约束，说明你个人拥有什么，并展示衡量方式。关键词帮助被发现；证据赢得面试。

### 5.1 bullet 结构

使用这个顺序：拥有的行动 + 困难环境 + 工程决策 + 可衡量的结果。示例：「在 18 个支持团队中主导部署了一个检索助手；构建了权限感知的数据摄入与一个 240 题的回归集，将中位回答时间降低 38%，同时把 groundedness 保持在启动阈值之上。」这句话展示了所有权、集成、评测、采用与业务结果，却不必自称 forward deployed。

### 5.2 要呈现什么

- 面向客户的发现、技术范围界定、方案设计与期望管理。
- 生产代码、集成、数据管道、API、部署、监控与事故响应。
- AI 评测、护栏、检索质量、模型权衡、成本、延迟与人工复核。
- 采用、节省的时间、带来的收入、降低的风险、可用性、质量，或其他由客户拥有的衡量。
- 一个你在模糊情境下做出的决策，以及你放弃的那个选项。

### 5.3 改前与改后

| 弱 | 更强 |
|----|------|
| 用 Python 和向量数据库构建了一个 RAG 聊天机器人 | 为 60 名分析师交付了一个权限感知的研究助手；创建了检索评测并把失败搜索减少了 31% |
| 与客户合作收集需求 | 把客户要求的仪表盘重构为异常工作流，与两名操作员试点，将人工复核时间减少 22% |
| 改进应用性能 | 在固定预算下引入缓存与模型路由，将 p95 延迟降低 41%，每个完成任务的成本降低 28% |

### 5.4 要删掉什么

删掉没有支撑的形容词、庞大的工具清单、挤占「已交付工作」的课程作业，以及只有团队是唯一行动者的 bullet。当工具能解释某个决策或满足岗位要求时保留它。如果你最强的故事仍然只是业余项目，先改进证据，再润色措辞；Build the Evidence 展示了怎么做。

## 7. 招聘 FDE 的公司

### 7.1 时效政策

本页链接到官方招聘搜索，而不是复制可能明天就过期的职位空缺。列在此处的公司曾公开使用 FDE 或相近的部署类头衔；链接并不表示今天每个地点都有岗位开放。

### 7.2 去哪搜索

| 公司/家族 | 要搜索的头衔 | 官方来源 |
|-----------|--------------|----------|
| Palantir | Forward Deployed Software Engineer、Deployment Strategist | Palantir careers |
| OpenAI | Forward Deployed Engineer、Solutions Architect、Deployment 角色 | OpenAI careers search |
| Anthropic | Forward Deployed Engineer、Applied AI、Solutions Architect | Anthropic careers |
| Google Cloud | Forward Deployed Engineer、Customer Engineer、Applied AI | Google careers |
| AI 与数据创业公司 | Forward Deployed Engineer、Applied AI Engineer、Field Engineer | 使用公司自己的招聘页 |

### 7.3 搜索相近头衔

同样的工作会以 Applied AI Engineer、AI Deployment Engineer、Field Engineer、Resident Engineer、Solutions Architect、Implementation Engineer、Customer Engineer 与 Deployment Strategist 等头衔出现。按职责筛选：直接客户工作、生产代码、集成、发现、上线、采用，以及反馈进产品。排除纯粹支持或带配额的岗位——除非那正是你想做的职业。

### 7.4 评估招聘帖

- 它是否明确要求交付生产代码，还是只要求演示与建议？
- 该岗位是售前、售后，还是负责整个客户生命周期？
- 预期有多少出差、同时服务多少客户、覆盖哪些地点？
- 实际要求什么样的经验带、AI 深度、安全知识与领域专长？
- 采用、可用性、交付、收入扩展与产品反馈分别如何加权？

### 7.5 保持研究时效

投递时把招聘帖保存为 PDF、记录日期，并针对那一版中的职责来准备。公司结构与面试回路的变化，比「常青」的职业指南更快。用 Company Differences 获取背景，然后用最新岗位核对一切。
