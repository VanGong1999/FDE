# 能力模型与成长路径

FDE 的能力不是「全会」，而是 **技术 × 客户 × 产品** 三角在项目压力下的组合拳。本篇给出可自评的模型与 Junior → Senior 里程碑。

---

## 1. 能力三角

```mermaid
flowchart LR
  Tech[技术交付]
  Cust[客户与组织]
  Prod[产品与杠杆]
  Tech --- Cust
  Cust --- Prod
  Prod --- Tech
```

| 顶点 | 内涵 | 转岗后端常见起点 |
|------|------|------------------|
| 技术交付 | 集成、数据、RAG/Agent、评测、观测、安全 | 通常最强 |
| 客户与组织 | 发现、对齐、推回、培训、政治与变更 | 通常最弱 |
| 产品与杠杆 | 抽象复用、反馈路线图、解决方案产品化 | 中等偏弱 |

**晋升往往卡在客户与杠杆，而不是又学会一个框架。**

---

## 2. 分级行为描述（可对照自评）

### L1 — 能执行（Junior / 新转岗）

- 在明确范围内独立完成模块（连接器、检索管道、简单 UI、评测脚本）
- 会写周报与风险，但范围由别人定
- 能跟用户做演示，但还不擅长主持发现工作坊
- 知道幻觉/权限风险，能按清单执行 guardrails

### L2 — 能负责一条试点（Mid）

- 独立跑完 Discover → Pilot 的窄场景
- 能把模糊需求收成可测成功标准
- 会设计 HITL、权限模型、基础 eval
- 能与客户 IT 推动 SSO/网络/数据问题到关闭
- 失败时有复盘，而不是只加班补丁

### L3 — 能端到端拥有复杂客户场景（Senior）

- 多干系人下的范围与优先级控制
- 生产级可靠性、成本、合规方案
- 把一次性项目沉淀为可复制 Playbook / 产品需求
- 带 1–2 名初级或协调跨职能
- 在「商务承诺」与「工程现实」之间做清晰决策备忘

### L4 — 能定义方法与业务线（Staff+ / 现场负责人）

- 多账户模式、招聘与辅导、重大风险升级路径
- 影响公司产品战略与包装
- 对外技术品牌与难点问题的最终裁决之一

## 3. 技能清单（雷达图用）

对每项打 1–5 分（1=听说过，3=能独立交付，5=能教会别人并定标准）：

### 技术

- [ ] 后端 API / 集成 / 异步任务
- [ ] SQL 与数据探查
- [ ] 前端或内部工具（能做够用的操作台）
- [ ] RAG 全链路
- [ ] Agent / 工具调用与权限代理
- [ ] Eval 设计与分析
- [ ] 观测、日志、追踪、告警
- [ ] 安全：密钥、PII、提示注入、审计

### 客户

- [ ] 访谈与工作坊 facilitation
- [ ] 成功指标与 ROI 叙述
- [ ] 冲突与范围控制
- [ ] 培训与变更管理
- [ ] 书面决策（备忘录、风险登记）

### 产品杠杆

- [ ] 识别可复用模式
- [ ] 写清产品缺口与现场变通
- [ ] 解决方案文档与模板化

## 4. 90 天成长剧本（新 FDE / 新转岗）

| 阶段 | 目标 | 具体动作 |
|------|------|----------|
| Day 1–30 | 变得有用 | 吃透内部平台与一个历史案例；完成小而真的任务；影子访谈 |
| Day 31–60 | 拥有子范围 | 负责试点的一块（如检索质量或权限）；建立 golden set 初版 |
| Day 61–90 | 可见结果 | 推动一次可度量改进；写复盘；提出一条产品反馈 |

面试时可把过往经历**映射**到这 90 天语言。

## 5. 后端转 FDE：补强优先级

| 优先级 | 补什么 | 怎么练 |
|--------|--------|--------|
| P0 | 问题拆解与成功标准 | 每周 2 道 Decomposition；项目里先写一页「谁/指标/约束」 |
| P0 | Eval 与失败分析 | 给 Demo 加 20 条黄金集 |
| P1 | 客户沟通与推回 | 用 [客户沟通](../02-交付方法论/客户沟通与阻力处理.md) 话术彩排 |
| P1 | 权限与企业集成 | 读懂 SSO/RBAC；在项目里画权限图 |
| P2 | 数据栈（按目标公司） | Snowflake/Databricks 基础 |
| P2 | 售前级演示能力 | 5 分钟讲清价值，不讲技术炫耀 |

详见 [05 能力补强](../05-能力补强/README.md)。

---

## 6. 反模式：虚假成长

- 只追新模型发布，不追评测与采用率
- 用加班掩盖范围错误
- 所有知识留在个人脑子里，不写 Runbook
- 把客户当「需求打印机」而不是合作方
