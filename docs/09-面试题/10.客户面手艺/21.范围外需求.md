# 你独自在客户现场。客户提出了范围之外的需求，而你的团队在另一个时区，此刻正在休息。现在就要做出决定。

这是纯粹的自主决策测试：没人可以请教，客户正在等候，而需求边界就在你面前。优秀的候选人给出的是一套**决策准则**，而不是凭感觉猜测。下面就是这套准则。


---
### 第20题
你独自在客户现场。客户提出了范围之外的需求，而你的团队在另一个时区，此刻正在休息。现在就要做出决定。


**一句话摘要（TL;DR）：要有一套决策准则，而不是靠猜：评估可逆性、影响范围，分清你是动手做事，还是做出承诺。愿意投入精力（现在就给可逆的需求做原型验证），但绝不轻易许诺（范围变更需要对接项目负责人协商）；并且在结束工作前留下书面记录。**

## 如何作答
这就是提炼出来的前沿部署工程师自主决策测试。这份工作，就是要你在远程现场代表公司做出判断。面试官不是要你简单回答“同意”或者“拒绝”；他们想看的，是你在问题刚说完时，就能清晰讲出一套决策准则。因为如果遇事逐个凭感觉判断，公司很容易踩坑。这套稳妥的准则会评估三个要素：**可逆性、影响范围、承诺风险**，并且区分“做一件提供帮助的事”和“向客户许诺一件事”——绝大多数实际风险，都出在这里。

### 一份高质量回答范例
“我的准则包含三项检验标准，我在走廊里花30秒就能完成判断。

第一：这件事是否可逆？如果客户的需求是只读操作、在沙箱环境内，或是可以撤销的，比如导出一份额外报表、基于我已经有权访问的数据写一个简短脚本做原型、草拟一份分析，我倾向于动手去做。如果操作会触碰生产环境、把数据转移到新位置、或是无法撤销，那答案就是‘今晚没法处理’，哪怕场面会尴尬。

第二：如果我判断出错，影响范围会有多大？报表出错：只是难堪。晚上7点独自给银行的生产环境做变更：直接上新闻头条。任何涉及安全边界、个人身份信息（PII）、资金流转，或是其他团队系统的需求，统一回复‘等明天早上给您答复’，哪怕客户态度再好，这条也没有例外。

第三：我是在动手做事，还是在许下承诺？这就是这道题里藏的陷阱。花两小时做出有用的东西，就算有问题也能挽回。但说出‘没问题，我们可以把这个加到本次部署里’，就变成了契约和规划里既定的内容，等我的团队睡醒之后，就要承接这个责任。
我愿意投入精力，但对承诺要谨慎：‘今晚我可以先给您做一个粗略版本验证可行性，帮我们摸清情况。至于这个需求算不算进本次合作范围，我这周会安排您这边的项目对接人和我的主管一起沟通确认。’”

放到这个场景里举例：运维主管让我额外把他们的库存数据接入我们正在搭建的流水线。这件事大体可逆，影响范围中等，真正的风险在于承诺。


我会这么说：“我现在能做的是：今晚拿一份样本导出数据做原型测试，验证这个方案到底能不能实现，明天您就能看到结果。但我不能单方面把这个需求纳入项目范围，这件事需要安排对接人和我的主管在周二沟通确认，我会发起这次沟通。”
然后，这一点没有商量余地：休息前留下书面记录。给我的主管发消息，写明客户提了什么需求、我做了哪些操作、我刻意没有做什么、哪些事项等待后续决策。核心目标：因为时差，团队是知情的，而不是被突如其来的状况打个措手不及。

我绝对不会做两件事：为了避免尴尬而隐瞒客户的需求；或是生硬地一口回绝所有请求，让客户以后有需求都不再找我。这两种做法都会丢掉驻场的优势——客户愿意直接把原始需求给到你。

| 自我拷问 | 如果满足（是） | 如果不满足（否） |
| ---- | ---- | ---- |
| 这件事明天可以撤销复原吗？ | 动手做，留下记录，等团队上班同步情况 | 不要独自拍板决定 |
| 这件事会不会改变项目范围、报价，或是做出承诺？ | 这件事不归我拍板。温和说明情况，并给出答复时限 | 可以继续处理 |
| 是否涉及安全、数据处理、权限访问？ | 无论客户怎么施压，立刻停止，不能操作 | 可以继续处理 |
| 你是否愿意在下次团队会议上，当众读出你这次的决定？ | 可以执行 | 不要做 |

---
高分答案，不是“我会做”或者“我会等”。而是讲清楚这套检验标准、当众推演这套判断逻辑，并且明确表达：相比周一爆出重大意外，我宁愿现在做出一个小小的拒绝。

### 面试官接下来可能追问的问题
- “这个需求是客户高层对接人直接提的，而且情况紧急。”
  职级和紧急程度不会改变这套准则，只会改变话术：依旧先完成可逆的验证工作，其余内容表述成“明早给您一个正式答复”，而不是简单说“不行”。
- “你做完原型，效果很好，结果你的主管因为范围蔓延很生气。”
  主动承担沟通疏漏的责任，而不是推翻判断：只要留下了书面记录，做原型这个选择本身没有错；坚持这套决策准则，同时听取反馈，校准自己的判断尺度。
- “如果说‘今晚做不了’，可能会丢掉这个订单怎么办？”
  直接说出你对这个预设的怀疑：很少有订单会因为晚12小时答复就丢单；但临时随口许下承诺，毁掉合作的情况却十分常见。

### 常见错误
- 只靠主观感受回答（比如“我会凭我的判断来处理”），讲不出清晰可复述的准则——这套准则本身，才是答案。
- 逞英雄去做不可逆的操作，只为让客户满意。Palantir这类公司的面试官，手里都有大量这种员工留下烂摊子、后续收拾残局的真实案例。
- 在团队睡醒之前，生硬地拒绝所有需求。这不叫判断力，这叫不作为，浪费了你驻场在客户现场的价值。
- 做了正确的事，但谁都没告诉。没有记录的单方面决定，哪怕最后顺利完成，也会摧毁信任。

---
“动手做事”和“许下承诺”的区分，是这套准则最核心的要点。值得明确一点：造成损失的几乎从来不是原型本身，而是这句话：“没问题，我们可以把这个加进去。”花两个小时搭建原型，后果可以挽回；口头承诺扩大项目范围，就变成既定规划，等你的团队睡醒就要接手这个包袱。**愿意投入精力，谨慎许下承诺**；而你留下的书面记录，就是用来保证团队知情，而不是突然被意外砸懵。
