# 为在线课程（或电商）目录设计一个推荐引擎
> 背景：每周都有新课程上线，并且大部分浏览用户处于未登录状态或是全新用户。这个问题最有意思的难点在于：当你几乎没有用户行为信号时，该如何给出推荐。另一个难点是：不能为了提升互动量，把目录做成标题党引流内容。


**一句话总结（TL;DR）**
系统分为两个阶段：候选集生成模块融合协同过滤嵌入向量与基于内容的双塔模型，保证全新课程、全新用户也可以被检索召回；之后是排序模块，目标优化选课转化（报名），同时加入课程完成率、退款率作为约束护栏，而不是单纯优化点击量。利用会话和用户意图信号，让未登录、首次访问的用户也可以参与排序；在输出最终列表之前，额外增加一层显式多样性控制和业务规则层。

---
## 如何解题
核心约束是**信号稀疏性**：很大一部分访问会话属于冷启动（没有历史行为），同时课程目录持续迭代，每周上新。所以纯协同过滤系统，恰恰对商业价值最高的新用户、新商品束手无策。
先提前问清楚三件事：
1. 冷启动（无历史）会话占比多少
2. 业务目标是什么：选课报名、营收、课程完成率、用户留存
3. 前端页面允许的延迟上限

然后把**候选集生成**和**排序**拆成独立阶段，这样可以独立优化检索召回和打分；**先确定业务目标，再选择模型**。

### 高分回答
系统拆分为【候选集生成】+【排序】两个模块。
候选集生成：把大概20万门课程的全量目录，在个位数毫秒内缩减到几百个合适的候选课程；排序模块用较重的模型，给这几百个候选打分。
把两者混在一起是经典错误：你无法对全目录跑复杂排序模型；只用简单检索器遍历全目录，得到的推荐结果会平淡、同质化严重。

候选集生成需要融合多路召回源，不要只依赖单一模型：
- ✅ 协同过滤：双塔嵌入模型（用户塔 + 物品塔），基于共同选课、共同浏览行为训练，使用近似最近邻检索（HNSW / FAISS）提供服务。这是有历史行为的老用户、老课程的主力召回链路。
- ✅ 基于内容的召回：专门解决冷物品、冷用户。物品塔输入课程标题、简介、大纲、讲师、分类、难度等级、文本嵌入向量。一门刚上线一小时的新课，在任何人交互之前就可以被召回。这是本题最重要的设计决策。
- ✅ 会话&共现召回源：“浏览过该课程的用户还浏览了”、分类下热门趋势、最近浏览→下一个浏览的关联。对于未登录用户、首次访问会话，这一路召回权重最高。

> 原图转为 Mermaid 流程图：
```mermaid
flowchart LR
    A[用户 + 会话上下文] --> C[候选集生成]
    B[目录 + 内容特征] --> C
    C --> C1[双塔协同过滤召回（ANN近似近邻）]
    C --> C2[基于内容召回（冷启动）]
    C --> C3[会话&共现召回]
    C1 & C2 & C3 --> D[~300个候选课程]
    D --> E[排序器：P(报名), E(完成率)]
    E --> F[多样性控制 + 业务规则层]
    F --> G[最终推荐列表]
    G --> H[点击、报名、退款、完成行为日志]
    H --> C & E[回流重新训练]
```

排序器可以用梯度提升树或者小型深度神经网络，给每个候选课程打分；特征分为三大类：
- 用户特征：技能水平、历史偏好分类、价格敏感度、设备
- 物品特征：评分、报名量、上新时间、价格、完课率
- 最重要：**用户-物品交叉特征 + 会话上下文**（在分类页停留时长、跳转过来的搜索词、购物车内已加入的课程）
交叉特征才是效果提升的核心；如果模型只有孤立的用户特征、物品特征，本质只是按热度排序。

**标签设计是这道题的决胜点：不要只用点击作为训练标签。**
一次点击只能说明“封面图吸引人”，不等于“这门课值得购买”。使用分级标签：
- 报名选课：强正样本
- 加入购物车：弱正样本
- 点击：极弱正样本
- 保障期内退款：强负样本（哪怕已经发生购买行为）

对于课程场景，第一模块学习进度/课程完成率是很重要的质量信号，需要纳入标签；因为单纯优化报名转化，模型会疯狂推荐低价、差评、容易退款的课程。
根据下游价值给标签设置权重，而不是把所有交互行为同等赋值为1。

举一个具体的分级标签方案（数值可以调优，**比例关系才是设计核心**）：
- 报名选课：1.0
- 加入购物车：0.3
- 点击：0.05
- 保障期内退款：-1.0
- 在报名后完成第一模块课程：给该报名标签 ×1.2 的增益系数

绝对值可以调整，但比例是关键：
点击权重0.05，代表20次点击才等价于1次加购，避免封面引流内容主导模型梯度；退款标记为-1.0，意味着“报名+退款”组合的总标签值归零，这种课程不会给模型带来正向信号。
向面试官讲清楚每一个权重比例背后的理由，远比说出花哨的排序损失函数更重要——损失函数本质上就是在优化这些数字定义的业务目标。

要有意识地选定优化目标：
- 互动指标（点击、停留时长）：容易提升，但容易被刷量、钻空子
- 转化指标（报名、营收）：业务核心指标，但是样本稀疏；容易诱导模型推荐高退款的劣质商品
- 完成率/留存：长期价值指标，但是反馈周期很慢

✅ 方案：**主目标优化预测报名概率**，同时把完课率、退款率作为护栏约束。防止模型靠推劣质课拉高报名量。
明确表述：**主指标：单会话报名量；护栏指标：退款率、30天完课率；上线标准：主指标提升，同时所有护栏指标不能变差**

| 目标 | 优点 | 缺点 | 定位 |
| ---- | ---- | ---- | ---- |
| 点击 / CTR点击率 | 反馈稠密、反馈快 | 鼓励标题党、引流封面 | 弱特征，永远不作为最终目标 |
| 报名 / 营收 | 业务核心指标 | 样本稀疏；会偏好高退款劣质课 | 主优化目标 |
| 完课率 / 留存 | 代表真实长期价值 | 反馈很慢（需要数周） | 护栏指标 + 标签重加权依据 |

### 冷启动方案，分两类单独处理
1. **冷物品（新课程）**：依靠内容塔，再加一块专门的探索流量配额：预留一小部分曝光流量（ε-贪心 或者汤普森采样）用来展示新课、收集交互数据，几天之后协同过滤模型就可以学到新课信号；否则新课永远拿不到交互数据，永远无法被排序，课程目录会慢慢枯竭。
2. **冷用户（新用户）**：依靠会话和意图信号：用户进入时的搜索词、访问的分类页面、前1~2次点击，可以让基于内容的排序器在本次会话内做个性化；在还没有任何点击行为时，兜底推荐分类热门、人工精选课程。

多样性层和业务规则层放在排序器、最终返回结果中间。
纯相关性排序会出现一堆几乎一模一样的Python同类课程。使用最大边际相关性（MMR）或者分类配额上限，打散推荐列表。
然后叠加业务规则——这类规则不应该让模型隐式去学习：
- 不推荐用户已经购买拥有的课程
- 支持推广位、讲师合约置顶扶持
- 过滤地域限制、下架淘汰内容
- 限制同一个讲师课程的展示次数上限

把这一层做成排序后的透明后置层，而不是放进模型特征，这样业务方修改规则时，不需要重新训练模型。

**线上实验评估才是真正的验收关卡**
离线指标：召回@k、MAP评估召回链路；AUC、NDCG评估排序链路。
⚠️ 但是离线指标只能说明新模型和历史日志行为保持一致，而历史日志本身就被旧模型的曝光偏差污染了。
必须通过A/B实验验证：
- 主指标：单会话报名量
- 护栏指标：退款率、30天完课率、目录覆盖率（监控热门垄断）、延迟
实验周期要足够长，要能观测退款（退款比点击滞后好几天）。
“CTR涨了，退款率也跟着涨”这个场景，正好说明为什么我们要同时监控转化和退款，而不是看到互动上涨就宣告成功。

**警惕反馈环路**
模型训练的样本来自它自己曾经曝光过的内容，所以模型会不断放大自己过去的选择；小众分类会悄悄从训练数据里消失。
缓解手段：
1. 前面提到的探索流量配额
2. 记录倾向性分数，使用逆倾向性加权（IPW）
3. 持续监控目录覆盖率，在业务发现问题之前，提前察觉推荐池收窄、马太效应

延迟指标：ANN近似近邻召回是个位数毫秒；几百候选的排序是几十毫秒；预计算用户嵌入、缓存热门列表，保证冷启动链路速度，页面p99延迟控制在100ms左右。

## 面试官接下来常追问的问题
1. **你的CTR上涨了，但是退款率也上涨了，发生了什么？**
模型学会优化点击，而不是用户真实价值。需要把优化目标改成转化，增加退款、完课率护栏，重新加权标签，让退款成为强负样本。点击只是代理指标，被模型钻空子了。

2. **一门新课程上线之后，连续几周没有流量，为什么？怎么修复？**
协同过滤无法给它打分，因为从来没有见过它的交互数据。如果没有内容塔、没有探索配额，新物品天然不可见。内容塔保证它可以被召回；探索流量拿到交互数据之后，协同过滤才能学到它。

3. **如何给未登录的首次访客做推荐？**
依靠会话意图信号：进入时的搜索词、访问分类页、前几次点击，驱动基于内容的排序器在本次会话内个性化；零点击兜底方案：分类热门、人工精选。

## 常见错误
- 拿点击训练排序模型，然后当成转化目标，最后疑惑营收为什么没有提升
- 把冷启动当成附带边角问题，而不是专门设计内容塔、探索配额（这是区分教科书标准答案和高分回答的关键点）
- 不用分阶段，直接用一个模型扫全课程目录
- 只按相关性排序，结果推一堆高度相似的课程
- 依靠离线NDCG就宣布模型成功，但NDCG只是和旧模型有偏日志对齐
- 忽略反馈环路，系统最后收敛到只推极少数爆款，目录覆盖率崩塌

---
## 核心要点总结
1. 分开【候选集生成（多路召回：协同过滤ANN、内容、会话）】和【排序】；永远不要用一个模型遍历全目录
2. 显式解决冷启动：内容塔保证新商品、新用户第一天就能召回；探索配额帮新商品积累协同过滤需要的交互信号
3. 优化转化目标，搭配完课率、退款护栏，而不是优化点击；分级标签设计，退款作为强负样本
4. 线上A/B实验验证，指标包含报名量 + 护栏（退款、完课、覆盖率、延迟），持续监控反馈环路，防止推荐池收缩


高级工程师的答题标志：**把冷启动作为核心约束，而不是事后补充**。内容塔保证从未曝光的新课上线当天就可以被检索；会话/意图信号让未登录访客在3次点击内就可以被个性化排序。优秀回答者会拆分召回和排序，选择转化目标（搭配营收/完课护栏）而不是原始点击，再加上独立的多样性、业务规则后置层。
面试官用“CTR涨了退款也涨了”这个追问，考察候选人是否理解模型目标被博弈、被钻空子的风险。


> 一个留到最后的跟进问题：护栏指标的时间窗口。退款、完课比点击滞后数天到数周。一个跑两周的A/B实验就算短期指标“通过”，模型也可能悄悄在推高退款的劣质课。你要说明：上线放行，必须基于已经完全成熟的指标；需要用延迟队列同期群看退款率，而不是和报名量用同一个统计窗口。
