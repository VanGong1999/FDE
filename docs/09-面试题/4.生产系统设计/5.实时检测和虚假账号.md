# 设计一套系统，实时检测机器人账号与虚假账号。

正样本占比可能只有千分之一；标签延迟返回、自带噪声；而且你上线模型的那一刻，攻击者就会开始试探它。这是一类很特殊的机器学习问题：数据本身会主动想办法骗过你的系统。因此这套方案，除了分类器本身，标签、延迟、处置成本同样是设计的核心。

---
### 一句话概要（TL;DR）
搭建双层系统：低延迟模型基于请求发生时的简易信号同步拦截明显的恶意行为；一套速度更慢的行为/图模型，基于会话维度对账号打分，用来识别隐蔽的团伙作弊。构建弱标签与延迟标签体系；根据误封禁和漏检机器人的不对等成本设定阈值；将置信度处于中间的可疑样本送入人工复核；同时监控对抗性数据偏移——因为攻击者会持续迭代来绕过你的防御。

## 思考切入点
首先理清三件事：模型输出的分数会触发哪些处置动作（静默标记、验证码挑战、限流、直接封禁），因为错误带来的成本决定阈值；延迟要求（登录、发帖校验需要100毫秒以内，周期性账号审计可以允许数秒）；标签来源——在这个场景里，做决策的当下几乎没有干净的真实标签。
要从**处置成本、标签的现实约束**倒推设计方案，而不是从模型正向推导。这个场景几个核心特点：极度样本不平衡（正样本远低于1%）、攻击者会持续自适应、标签稀缺、质量差、滞后。

## 高质量回答
按照延迟高低、信号丰富程度拆分检测链路。
**实时层**：针对每一次敏感操作（注册账号、登录、发帖、发送好友请求、下单），在几毫秒到几十毫秒内完成打分，使用轻量特征：请求速率、IP/ASN信誉、设备指纹、请求头异常、注册时长、特征库里简单的频次统计。它的职责是同步拦截明显、大规模的恶意行为，并触发风控摩擦措施。
**近实时层**：在会话或者滚动时间窗口内对账号打分，使用成本更高的行为特征、图特征：行为时序熵（脚本操作的时序往往比真人更规律；不过这个信号本身偏弱，攻击者会增加随机抖动规避）、图信号（共用设备/IP、高度相似的关注关系图、注册时间聚集、账号-设备-IP图经过图神经网络GNN得到的嵌入向量）、跨账号内容相似度。
团伙虚假作弊行为，单独看每个账号都看不出异常，但放在集群视角就非常明显，所以图模型层，专门用来抓轻量实时层漏掉的批量攻击。

> 流程图说明：
账号行为 → 特征库（频次、设备、IP信誉）→ 实时模型（低延迟）
- 高分：执行风控处置（挑战/限流/封禁）
- 不确定：送入人工复核队列，复核结果生成校正标签，存入弱标签库，用于模型重新训练
- 低分：放行
另外一条链路：账号行为送入近实时图/行为模型，输出结果同样流向风控处置和标签回流链路

标签才是真正的难点。做决策的当下，你几乎无法判断一个账号是不是机器人。要从多种弱、滞后的数据源融合构建标签：人工复核确认标签、后续因为垃圾内容/欺诈被处置账号的标签；规则生成的弱标签（异常速度、已知机器人IP段）、蜜罐/陷阱标签（只有自动化程序才会触发）；下游延迟反馈标签（拒付、大量用户举报、几天后下架违规内容）。
把这些标签视作带噪声的数据，使用**正样本-无标注学习（PU Learning）**，因为“暂时没抓到”不等于“账号是正常账号”。标签延迟会带来业务问题：如果要一周才能确认一个机器人账号，你的训练集永远落后于当下的攻击手段，这也是为什么监控和快速重训练是这套系统的支柱。

样本不平衡与评估指标。正样本占比低于1%时，准确率完全没有参考价值，甚至ROC-AUC也会误导你。优化目标选用PR-AUC，在实际上线的阈值下，重点汇报精确率、召回率，同时统计针对已知攻击家族的召回率。类别权重、Focal Loss的效果优于单纯过采样；在对抗性表格数据、图数据上使用SMOTE，很容易生成不符合真实情况的虚假正样本，不是好方案。
阈值是由业务决定的，核心是**非对称成本**：误封一个付费真实用户的代价（用户信任、客服压力、流失、舆情）远高于放过一个机器人账号。所以对于硬性封禁操作，偏向保证高精确率，接受更低的召回；置信度偏低的样本使用更柔和的手段（验证码、限流、影子限制），这类操作就算误判，代价低、可以撤销。更清晰的方案是**按分数区间分层处置**，而不是简单一条“封禁/放行”分界线。

| 分数区间 | 处置动作 | 理由 |
| ---- | ---- | ---- |
| 极高置信度 | 自动执行封禁/拦截 | 误判风险足够低；数量太大，人工处理扛不住 |
| 不确定中间区间 | 挑战（验证码、二次验证、限流）或人工复核 | 可逆的风控摩擦；人工判定，同时产出标签 |
| 低分 | 放行，持续留存日志 | 漏检成本低；后续行为模型依然有机会检出 |

对抗性数据偏移与反馈闭环。和观看时长预测这类任务不一样，这里的数据分布背后有对手。一旦你屏蔽了某一类信号，攻击者立刻改造它（轮换IP、随机时序、模仿真人行为曲线），静态模型几天内效果就会衰减，而不是几个季度。
应对手段：持续监控分数分布、单特征偏移；基于蜜罐账号持续跟踪已知恶意账号的召回率；定时、触发式重训练；把稳定简单信号和模型学习到的信号做集成，避免某一个特征被绕过就导致整个模型失效。一部分信号保密、轮换陷阱规则；完全公开的规则集，等于给攻击者写好了绕过说明书。
小心反馈闭环陷阱：如果模型只能见到通过它过滤后的账号，训练数据会慢慢偏向“伪装得很像真人的机器人”——这恰恰是攻击者的目标，也是采样陷阱。加入探索机制：偶尔放行部分标记可疑的账号，开启影子监控，持续观察攻击者新的规避手段。

**人在环路（Human-in-the-loop）不是兜底方案，而是标签生产引擎和安全阀门**
不确定分数区间的样本进入复核队列；人工判定结果产出高质量标签，同时提供误判申诉通道，还能在模型学到新攻击类型之前，提前识别从未见过的新型攻击。根据审核人员处理能力，调整区间宽度，控制队列流量。

## 面试官接下来常追问的问题
- 问：攻击者一夜之间改变行为，召回率暴跌，怎么办？
答：提前预期这种情况。偏移监控、蜜罐召回告警会先触发；使用刚人工标注完成的标签快速重训练；临时提高稳定基础信号、图聚类结果的权重（哪怕单账号行为变了，批量攻击账号依然会聚集）；在模型恢复效果前，拓宽人工复核区间。
- 问：怎么避免封禁真实用户？
答：非对称阈值+分层处置（先挑战，不到万不得已不封禁）、人工复核区间、申诉通道、在封禁阈值下评估精确率；任何新模型正式上线前，先用影子模式验证，不直接执行处置动作。
- 问：为什么用图模型，而不是只用单账号特征？
答：团伙作弊在单个账号维度看不到异常，只会以集群形式暴露（共用设备/IP、同步注册、高度相似关系网络）；图神经网络或者社区检测，可以抓到实时请求模型识别不出的批量攻击。
- 问：做决策的时候根本不知道真实结果，标签从哪里来？
答：融合人工判定、下游反馈（拒付、大量举报）、规则弱标签、蜜罐；标签自带噪声，采用PU学习——未标注样本不等于负样本。

## 常见错误
把它当成一个普通的不平衡分类任务：只使用SMOTE、优化F1，完全不考虑攻击者；在1%的低占比场景下优化准确率或者ROC-AUC，而不用PR-AUC、上线阈值下的精确率召回；只设置单一封禁/放行阈值，忽略误封禁的代价远高于漏检；假设做决策时就有干净标签，但现实中标签会延迟好几天、质量差；上线模型之后没有偏移监控、没有重训练机制，任由模型随着攻击者迭代悄悄失效；没有人工介入流程，既丢掉申诉通道，也失去高质量标签来源。

## 核心要点总结
1. 双层架构：50ms以内的轻量信号前置拦截层 + 速度更慢、用来识别团伙攻击的行为/图模型
2. 标签稀缺、微弱、滞后；标签来源包括人工复核、下游结果、规则、蜜罐；未标注样本 ≠ 正常样本
3. 阈值由非对称成本决定：误封禁代价远大于漏检；分层响应，不确定样本交给人工
4. 数据分布存在对抗性；监控偏移、快速重训练、部分信号保密；评估指标使用PR-AUC、蜜罐召回率，不要看准确率

资深面试官的考察重点：要看候选人是否理解这是**带稀缺标签的对抗性问题**，而不是普通的不平衡分类任务。优秀候选人会把实时轻量模型和慢速图/行为模型分开；把精确率召回的工作点和错误处置成本（误封真人 vs 放过机器人）绑定；设计弱标签、延迟标签和人工复核流程。
那种听起来严谨，但只说“用SMOTE、优化F1”，不提标签延迟、数据偏移、假阳性非对称代价的回答，是不合格的。面试官会追问：“攻击者一夜之间改了行为，召回崩了怎么办”，用来考察候选人对重训练、监控体系的理解。



回答“召回率一夜暴跌”这个问题，最能区分有没有真正做过风控反作弊系统的人。
单账号行为，是攻击者最容易修改的东西；但是团伙攻击的聚集特征很难改掉：共用设备、同步注册、近似的关系图。
所以当请求侧的实时模型效果下滑时，要加重图模型层的权重，同时拓宽人工复核区间，给模型留出重新训练的时间——因为这种协同聚集信号，往往能扛过让单账号特征失效的规避手段。
