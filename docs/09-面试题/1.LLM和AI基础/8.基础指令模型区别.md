# 基础模型（base model）与指令模型（instruct model）的区别是什么？客户为什么要关心这个？


**一句话摘要**：基础模型是原始预训练模型（一个强大的自动补全工具，只会遵循文本模式，不会遵循指令）；指令模型在预训练之后增加了后训练流程（有监督微调SFT + RLHF/DPO人类偏好对齐），使其能够听从指令、扮演助手角色。大约95%的企业业务场景都应该选用指令模型；而开源权重模型需要重点留意**对话模板（chat template）**这个坑。

## 流程图说明
预训练（Pretrain）→ 有监督微调（SFT）→ 基于人类反馈的强化学习（RLHF）
- 预训练：万亿级token数据输出 → **基础模型：下一个token预测器**
- SFT：使用示范样本数据
- RLHF：基于人类偏好数据
> **指令模型：可以遵从指令**

> 预训练赋予模型知识；对齐技术（SFT、RLHF）让模型学会服从指令。

## 答题思路
答题结构：讲清楚预训练产出什么、后训练新增了什么、二者行为上可观测的差异。然后重点回答“客户为什么关心”这部分，大部分求职者只会回答前半部分。

## 高质量参考答案
基础模型是完成预训练之后得到的模型：它基于互联网规模的文本做**下一个token预测**。它是一个极其强大的自动补全模型，拥有海量知识，但它完全没有“充当助手”这个概念。如果你给它提示：“法国的首都是什么？”，它可能继续输出更多测验题，因为从统计概率上看，这是文本最合理的续写。**它只会学习文本模式，不会遵从人的指令。**

指令模型（对话模型）= 基础模型 + 后训练流程：
1. 有监督微调SFT：用大量“指令‑回答”样本对模型微调，教会模型遵循指令的输出格式；
2. 偏好优化（RLHF 或者 DPO）：依据人类偏好排序结果继续调优，塑造模型的有用性、语气、拒绝回答能力与安全行为。

指令模型还有一个关键配套产物：**对话模板（system/user/assistant角色格式）**。如果使用错误的对话模板，模型输出质量会悄无声息地下降；这是本地私有化部署中真实存在的bug。

对话模板这个问题需要具象理解，它的危险之处在于：**不会报任何错误**。指令模型在后训练阶段，是被包裹在特定格式脚手架的对话数据训练出来的，格式示例：
```
<s>[INST] 你是一名客服助手。
我该如何重置密码？ [/INST]
```

如果你把同样的模型，直接输入裸文本字符串：`我该如何重置密码？`。模型依旧可以流畅生成文本，生成流畅是大模型的基础能力，它不会失败。但是后训练赋予模型的所有能力全部受损：遵循指令的能力、拒绝不当请求、输出格式约束，全部会出现不同程度衰减，日志里却不会出现任何报错。

私有化部署典型现象就是业务反馈：“我们本地部署的模型，效果明显比官方API差”。排查方法很简单：用20组完全相同的提示词，分别跑官方托管API和你的私有化部署。如果输出质量出现差距，就要检查推理服务层有没有正确套用模型配套的对话模板。大部分推理服务框架都支持对话模板，但必须手动配置。

### 客户为什么关心？
1. **默认选型**：95%及以上企业场景（对话、RAG、信息抽取、智能Agent），都应该选用指令模型。企业现场工程师要明确这一点；如果给客服聊天机器人推荐基础模型，属于选型失误。
2. **模型行为来自后训练**：拒绝策略、输出篇幅、JSON格式输出能力、模型“人设”，即使底层基础模型权重接近，不同版本也会不一样，这都是后训练带来的。当客户反馈新版本模型行为变化，根源在后训练。
3. **什么时候选基础模型**：需要定制特殊输出格式、科研、自己从零搭建对齐流程，这种场景适合基础模型。很多开源权重（Mistral、Llama）只会发布基础模型权重，企业自建部署团队会直接面临这个选型。
4. **安全预期**：基础模型完全没有安全护栏。客户直接部署原始开源权重，需要明白API版本自带的拒绝、安全防护，在基础模型上是不存在的。

## 面试官后续追问（高频）
1. **RLHF实际优化的是什么？**
训练一个基于人类偏好对比打分的奖励模型；然后优化大模型，让它在奖励模型拿到高分。同时要讲副作用：模型会迎合用户，即使自己不懂，也会输出听起来非常自信的错误内容。

2. **为什么微调基础模型，效果有时比微调指令模型更好？**
微调基础模型，不会和模型已有的后训练对齐效果冲突，可以完全掌控模型行为；但是代价是你需要自己实现指令遵循、安全防护，工作量很大，多数场景得不偿失。

3. **客户拿指令模型做微调，做完之后对话效果反而变差，是什么原因？**
灾难性遗忘，或者微调数据集带来分布偏移。缓解方案：混入通用对话数据、使用小秩LoRA微调、增加评估校验环节。

## 常见错误
- 基础模型和指令模型定义讲对，但答不出客户业务层面的影响；面试的核心得分点恰恰就是后半部分。
- 混淆指令微调、RAG、客户私有数据微调三者概念。
- 完全不知道对话模板的存在，代表求职者没有实操过开源权重模型；Mistral、Cohere面试官会专门考察这点。
- 认为RLHF让模型变得“事实正确”。RLHF优化的是**人类偏好**，这正是幻觉内容听起来非常笃定自信的根源。

## 核心要点总结
1. 基础模型学习文本模式；指令模型依靠后训练（SFT+RLHF/DPO）获得遵从指令的助手行为。
2. 绝大多数企业业务，优先选指令模型；仅在定制特殊行为、科研、自建对齐流程场景，才选用基础模型。
3. 使用开源权重模型时：对话模板用错，输出悄悄变差，且无报错；基础模型本身不带任何安全护栏。

### 编者备注
使用开源模型时，**对话模板是隐形杀手**：加载指令模型，输入原始裸文本，不套system/user/assistant的格式脚手架，输出质量直接下降，却不会有任何报错。很多做私有化部署Mistral、Llama的公司，面试官专门会问：“为什么我们本地部署的模型效果，明显不如官方API？”用来筛选候选人是只调用过托管API，还是真的动手做过私有化部署。

### 讨论区留言

随着工具调用能力普及，对话模板这个坑变得更严重了。现在模型后训练阶段，是基于一套特定的工具调用序列化格式训练的（特殊标记符、JSON规范）。私有化部署如果自己手写提示词，而不是直接调用tokenizer内置的对话模板，工具调用输出看起来像那么回事，但内部格式会有隐蔽错误。就会出现：普通对话看着没问题，但Agent智能体链路效果明显变差，也就是“私有化部署变笨”这个bug。
