# 数据工程基石课程

> 整理自 Awesome Forward Deployment Engineering（Pier Paolo Ippolito / Paolo Perrone 等维护）。  
> FDE 任务常从「数据审计」开始：理不清客户二十年的脏 schema，就无法在其上建 AI。

---

## 1. 为什么是基石

前线交付很少从「完美数据湖」起步。你面对的是损坏 schema、影子 Excel、无主键的 CRM、以及「两周后数据就好」的承诺。数据工程能力决定你能否在第一周建立可信基线。

---

## 2. 必掌握能力

### 高级 SQL 与查询调优

不止会 `JOIN`。要掌握：

- 窗口函数、递归 CTE  
- 读 `EXPLAIN`，判断为何扫描了 10TB  
- 面向客户仓库的分区/聚簇直觉（见 [Snowflake/Databricks 现场](./Snowflake与Databricks现场.md)、GCP BigQuery 专篇）  

### 面向现实的数据建模

- **星型模型（Star Schema）** vs **一张大宽表（OBT）**  
- 在写入性能与业务可读性之间取舍  
- 明确 **System of Record（权威源）**，避免建在过期副本上  

### Medallion（铜银金）架构

| 层 | 含义 |
|----|------|
| **Bronze** | 原始落地，尽量不可变 |
| **Silver** | 过滤、关联、清洗后的「单一真相」 |
| **Gold** | 业务就绪聚合，驱动 UI / AI |

### 分布式计算

- 理解 Spark/Ray 分区  
- 会排查 **Data Skew** 与 **OOM**（客户数据超出本机内存是常态）  

### 数据质量与可观测

为数据做「断路器」：上游坏了应先告警，而不是等 CEO 看见坏看板。

---

## 3. 现场第一周建议动作

1. 画数据源地图（系统、刷新、owner、质量坑）  
2. 抽样画像：空值率、主键、时间戳缺失  
3. 点名权威源 vs 影子 IT  
4. 定 Bronze→Silver 最小路径，而不是一次建全湖
