# 变更管理与培训设计进阶

技术门禁通过后，**采用**仍可能失败。本篇把变更管理做成可执行设计，而不是「发个上线通知」。

---

## 1. 变更的本质

用户被要求改变习惯。阻力来自：多一个入口、怕错、怕被考核、不信任 AI、旧流程有灰色空间。FDE 要管理的是**行为变化**，不是功能列表。

---

## 2. 变更设计画布

| 块 | 问题 | 产出 |
|----|------|------|
| 受众分段 | 谁是日用/偶用/否决者？ | 分段名单 |
| 价值主张 | 每人多得到什么、少失去什么？ | 一句话/角色 |
| 工作流嵌入 | 是否出现在原系统里？ | UX 决策 |
| 激励与考核 | 是否与 KPI 冲突？ | 与管理者对齐 |
| 能力建设 | 需要什么技能？ | 培训大纲 |
| 支持 | 前两周谁答疑？ | 值班表 |
| 反馈 | 错误如何进系统改进？ | 上报路径 |
| 成功叙事 | 四周后讲什么故事？ | 指标+引言 |

---

## 3. 培训设计（够用即可）

### 30–45 分钟上手课结构

1. 解决什么问题 / 不解决什么（5）  
2. 现场演示主路径（10）  
3. **故意演示失败与如何升级**（5）——建立信任  
4. 学员实操 2 个工单（15）  
5. 支持渠道与考核说明（5）  

### 材料包

- 一页速查（截图）  
- 3 分钟录屏  
- FAQ（含「AI 错了怎么办」）  
- 管理员 Runbook  

---

## 4. 采用曲线运营（上线 14 天）

| 日 | 动作 |
|----|------|
| 0 | 上线；冠军用户名单启动 |
| 1–3 | 每日答疑；收集前 20 个摩擦点 |
| 4–7 | 修复 Top 摩擦；公开变更日志 |
| 8–14 | 看采用漏斗；一对一访谈不采用者 |
| 14 | Review：扩/停/改  

指标建议：邀请→首次使用→周留存→建议采纳率/任务完成率。

---

## 5. 与「抵抗」共处

| 现象 | 可能原因 | 动作 |
|------|----------|------|
| 注册不用 | 入口远、无价值 | 嵌入原工作台；找真痛点 |
| 用后差评 | 质量/速度 | 失败案例分析 |
| 阴奉阳违 | 考核冲突 | 与管理者改 KPI |
| 超级用户垄断 | 知识未扩散 | 文档化；轮值冠军 |

---

## 6. 解决方案产品化（轻量）

每个成功试点沉淀：

1. 问题陈述模板  
2. 架构参考与非目标  
3. Eval 集种子  
4. 培训材料  
5. 门禁清单  
6. 已知限制  

这就是「前线 → 产品」飞轮，面试与晋升都加分。见 [能力模型](../01-角色认知/能力模型与成长路径.md)。
