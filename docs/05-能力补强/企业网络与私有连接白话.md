# 企业网络与私有连接白话

客户常说：「数据不能出网 / 要专线 / 要私有化」。本篇帮助 FDE **把需求翻译成可选项**，并与云/网络工程师协作——不是让你考取网络证书。

---

## 1. 常见要求与对应手段

| 客户说的话 | 可能真实需求 | 常见手段 |
|------------|--------------|----------|
| 不能出公网 | 流量不经公共 Internet | VPC 内资源、私有链路、专线 |
| 不能给第三方 | 禁止外部模型商 | 本地/专有模型，或合同+技术控制 |
| 固定出口 | 防火墙白名单 | NAT 网关固定 IP |
| 要专有云 | 隔离部署 | 厂商专有区域/私有化套件 |
| 要审计一切 | 可追溯 | 镜像日志、私有存储 |

**先澄清「不能出」是禁止 DNS 出站，还是禁止数据被用于训练，还是禁止离开国境。** 三者方案完全不同。

---

## 2. AI 应用典型拓扑

```text
用户 → 企业SSO → AI应用(VPC)
              → 向量库/DB(VPC)
              → 工具/业务API(VPC或私有链路)
              → 模型推理：
                    A) 同VPC私有模型
                    B) 经私有链路到厂商专有端点
                    C) 受控出站到公有API（合同+DLP）
```

你要在设计文档里**画选中的那条**，并标注数据驻留区域。

---

## 3. FDE 检查清单

- [ ] 数据分类：公开 / 内部 / 机密 / 受限  
- [ ] 哪一类允许出站到模型商？  
- [ ] 日志存在哪、留多久、谁可查？  
- [ ] 密钥在哪轮换？  
- [ ] 故障时降级是否仍符合驻留？  
- [ ] 供应商 subprocessors 列表是否过法务  

---

## 4. 与「私有化」决策

走 [架构决策树](../03-AI落地/架构决策树.md)：许多合规可通过 **RAG + 网关 + 日志管控 + 合同** 满足；私有化带来运维与版本滞后成本，需书面权衡。
