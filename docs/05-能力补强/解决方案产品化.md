# 解决方案产品化（Packaging）

前线成功若不能复制，公司与客户都不可持续：你会变成「唯一会修的人」，销售无法规模化，产品得不到真实信号。本篇讲如何把一次性项目收成 **可售、可交付、可升级的解决方案包**。

衔接：[能力模型](../01-角色认知/能力模型与成长路径.md)、[Review 阶段](../02-交付方法论/Discover-Design-Deploy-Review.md)、[变更管理](./变更管理与培训设计.md)。

---

## 1. 为什么要产品化

| 不产品化的症状 | 后果 |
|----------------|------|
| 每个客户从零发现、零文档 | 交付周期与毛利失控 |
| 知识在英雄脑子里 | 休假/离职即事故 |
| 定制分支无限分叉 | 无法升级，安全补丁跟不上 |
| 现场洞见不回流 | 核心产品永远慢客户一步 |
| 销售承诺「都能做」 | 范围爆炸，品牌透支 |

**产品化不是「停止定制」**，而是：标准路径走 80%，定制走配置/插件，极端需求走加价与排期。

---

## 2. 什么叫「包好了」

| 维度 | 项目制（未包） | 产品化解决方案 |
|------|----------------|----------------|
| 范围 | 每次从零谈 | 有标准范围、排除项、加价菜单 |
| 交付物 | 人脑 + 聊天记录 | 模板、脚本/IaC、文档、培训、Eval |
| 评测 | 临时演示题 | 种子黄金集 + 量规 + 通过线 |
| 人员 | 依赖英雄 | 二号位可按手册交付 |
| 安全答疑 | 每次重写 | 标准数据流图 + FAQ |
| 反馈 | 散落聊天 | 结构化需求进产品 Backlog |
| 商业 | 说不清卖什么 | 包装名、层级、成功案例一页纸 |

### 成熟度阶梯（自评）

| 级别 | 状态 | 标志 |
|------|------|------|
| L0 | 一次性项目 | 只有代码仓库 |
| L1 | 可复述 | 有 README + 问题陈述模板 |
| L2 | 可交接 | 有 Runbook、培训、Eval 种子 |
| L3 | 可复制销售 | 有适用/不适用、标准 SOW 附件、第二家客户复用 |
| L4 | 可产品化回流 | 配置化扩展点 + 正式产品需求已立项 |

FDE 个人目标：每个成功试点至少推到 **L2**；战略级方案冲 **L3**。

## 3. 从试点到解决方案包：六步

```mermaid
flowchart LR
  Pilot[试点成功]
  Harvest[收割可复用件]
  Bound[写适用边界]
  Package[组目录与版本]
  Trial[第二家客户试投]
  Feedback[回流产品]
  Pilot --> Harvest --> Bound --> Package --> Trial --> Feedback
```

1. **收割**：问题陈述、架构决策、Eval、培训、门禁清单、已知限制  
2. **抽象**：去掉客户专有名词；把硬编码改成配置  
3. **划界**：明文适用 / 不适用 / 加价项  
4. **组包**：按下文目录落盘并打版本号  
5. **试投**：第二个客户只用手册 + 少量辅导（检验是否真可复制）  
6. **回流**：把反复出现的缺口写成产品需求，而不只是现场补丁

## 4. 解决方案包最小目录

```text
solution-name/
  README.md              # 一句话价值、适用/不适用、版本、联系人
  CHANGELOG.md           # 版本变更
  discovery/             # 访谈提纲、问题陈述、成功指标模板
  architecture/          # 参考架构图、ADR、决策树链接
  infra/                 # 部署步骤、Terraform/Helm/脚本、环境变量表
  eval/                  # 种子黄金集、量规、如何跑分、基线数字
  playbooks/             # 运行手册、故障树、回滚、值班
  training/              # 速查、录屏脚本、FAQ、管理员手册
  security/              # 数据流、威胁模型答疑、权限模型
  commercial/            # 标准范围、排除项、加价菜单、案例一页纸
  config.example/        # 可复制的配置样例（无密钥）
```

### README 必须有的段落

1. 解决谁的什么问题（用户 + 指标）  
2. 适用 / 不适用  
3. 标准交付周期与依赖（客户侧 owner、数据、SSO）  
4. 快速开始（部署最小路径）  
5. 版本与支持策略

## 5. 适用 / 不适用（必须写狠）

写得越清楚，越能保护毛利与品牌。

**示例：企业制度问答助手**

| 适用 | 不适用 |
|------|--------|
| 制度/SOP 类、可回源引用 | 开放域医疗诊断、法律意见替代律师 |
| 有文档 ACL 或可建等价模型 | 「无数据源凭空智慧」 |
| 错误可 HITL / 升级人工 | 要求全自动且零差错的高危决策 |
| 单事业部试点可度量 | 「第一周全集团上线」且无门禁 |

**加价菜单示例**

- 多语种 / 多租户  
- 私有化与气隙投递  
- 与冷门业务系统深度写回  
- 定制评测集共建（专家标注工时）

## 6. 配置化 vs 分叉：怎么避免「雪花客户」

| 做法 | 结果 |
|------|------|
| 每个客户一个长期分支 | 半年后无法合并，安全补丁噩梦 |
| 主线 + 配置（YAML/Feature Flag） | 可升级 |
| 主线 + 正式插件接口 | 深度定制仍可升级 |
| 主线 + 一次性脚本（标明 discard） | 可接受，但要进债务清单 |

**规则**

- 方案版本 `v1.2.0` ≠ 客户环境名  
- 客户特有逻辑优先配置；其次插件；最后才是「付费分叉 + 明确日落日」  
- 每个客户的分叉债务写入 Review，并有退役计划

## 7. 商业包装（和销售对齐的一页纸）

FDE 不必变成销售，但要提供**可售语言**：

```text
名称：
一句话：
目标买家（角色）：
标准成功指标：
标准周期：
客户必须具备：
明确不做：
参考案例（脱敏）：
```

没有「明确不做」，销售容易超卖，工程买单。

## 8. 合成小案例：从一家到三家

**背景**：在客户 A 做成「报销制度问答」试点，采纳率 45%。

| 动作 | 结果 |
|------|------|
| 收割 Eval 80 题、培训速查、ACL 数据流图 | L2 |
| 抽象连接器配置，去掉客户 A 部门名 | 可给客户 B |
| 写明不适用「薪酬密级文档未分级」 | 挡掉一个高危商机 |
| 客户 B 用包交付 4 周（A 曾用 10 周） | 验证可复制 |
| 把「活动生效窗口元数据」提给产品 | 回流成功 |

面试话术见文末。

## 9. 反模式

| 反模式 | 症状 | 纠正 |
|--------|------|------|
| PPT 产品化 | 只有幻灯片没有 Eval/Runbook | 按目录补齐 L2 |
| 伪标准 | 名叫 v1，实则每客不同分支 | 强制配置化审查 |
| 无限承诺 | 适用边界写「都可以」 | 重写不适用清单 |
| 只给代码不给培训 | 二号位不会交付 | 补 training/ + 试投 |
| 从不回流产品 | 现场重复造轮 | 每个季度提 1–3 条产品需求 |
| 过早平台化 | 一家客户就做大中台 | 先 L2/L3，再平台 |
| 过早通用化 | 拿通用 Chat 能力找问题 | 先打穿具体客户问题，再抽象（见下节） |
| 服务收入绑架 | 短期人天很好，战略视野丢失 | 书面二选一：赌产品 vs 卖服务 |

## 10. 零到一 → 可复用：公开路径示例（OpenAI FDE）

> 精读补充自 [OpenAI FDE 访谈](https://www.youtube.com/watch?v=cBD7_R-Cizg)（Colin Jarvis）。数字与产品名为公开口述，以官方为准；此处只抽取**可迁移节奏**。

| 阶段 | 做法（意译） |
|------|----------------|
| 具体客户 | 客服难靠手写 400 条政策提示扩展 → **参数化指令与工具**，每个意图包评估 |
| 框架化 | 内部开源框架（口述中的 Swarm）验证可复制 |
| 第二客户加压 | 更复杂运营商场景（口述 T-Mobile）扩展同一原语 |
| 产品化 | 与产品共建 Agent SDK / AgentKit 等，成为标准工具箱 |

节奏口诀：**零到一 → 再做 2–3 次提到约 50% 可复用 → 再推规模化业务。**  
FDE 团队是**零到一攻坚**，默认不长期驻留运营；交客户工程或伙伴接手。

### 给创始人/负责人的三条（同访谈）

1. **先写清目标**：靠服务收入，还是赌产品成功带来的收入？不要假装两者兼得。  
2. **敢于对不战略的高价说不**——最终必须能导向产品或平台（或明确的研究学习）。  
3. 容量可按两轴排：**产品假设**（找设计伙伴）× **行业大问题**（半导体、生命科学等）。

瞄准问题时优先**高价值、可证明 ROI** 的真痛点，而非边缘 Demo 用例（与摩根士丹利类「核心业务」选型同构，见 [案例 07](../06-行业案例/07-Morgan-Stanley-OpenAI.md)）。

## 11. 现场产品化纪律（多公司共识）

> 补充自 [SPC](https://www.youtube.com/watch?v=hWuoH-ODDNc)、[Factory](https://www.youtube.com/watch?v=wpOA-UXynoM)、[Cognition](https://www.youtube.com/watch?v=RVxym6mmIns)。

| 纪律 | 做法 |
|------|------|
| 固定成本 / 经常性价值 | 问：是否以某种固定成本持续交付经常性价值？（软件经济 vs 咨询经济） |
| 学习飞轮 | 每个客户加快下一次定制/智能体交付；元智能体加速构建新智能体 |
| 共同障碍 → 平台 | 「我们厌倦了每个客户都处理这个」→ 一次性进平台 |
| 路线图向左拉 | 机会出现时用可泛化架构先做，而不是一次性脚本 |
| FDE 是平台第一用户 | 他们觉得有价值、愿意在上面构建，才是平台真测试 |
| 扩张/收缩阶段 | 初创不同阶段要不同 FDE 画像；保持谦逊与轮换 |
| 自动组装 | 万人级、数万库组织不能靠手动安装；部署目标是 self-assembled |
| 每个人都是 GTM | 目标是客户成功；前向部署边界模糊时，用结果而非部门墙定义工作 |

**Palantir 伤疤组织提醒：** FDE 曾起义因平台对现场无用——创办公司时要高信任对话，确保不是去做无限咨询。Jason 总结：FDE 是巨大 **feature**，不是 bug——前提是有产品回流。

## 12. 检查清单（发布 v1.0 前）

- [ ] 适用/不适用/加价项已与销售或主管对齐  
- [ ] 第二个人（非作者）按手册完成一次模拟部署  
- [ ] Eval 种子可跑，有基线数字  
- [ ] 安全一页纸通过内部评审  
- [ ] 已知限制对客户可见  
- [ ] 版本号与 CHANGELOG 就绪  
- [ ] 至少一条产品回流建议已挂号  
- [ ] 能用一句话说清：经常性价值是什么、固定成本是什么

## 13. 面试与晋升怎么讲

弱：「我做过很多客户项目。」  

强：

> 我将客户 A 的报销制度问答试点沉淀为内部解决方案包（含 Eval、ACL 数据流、培训与适用边界）。客户 B 交付周期从约 10 周降到 4 周；并把「文档生效窗口」回流为平台需求。我明确拒绝了无分级密薪场景，避免合规风险。

准备数字：周期、采用率、复用次数、挡掉的错误商机。
