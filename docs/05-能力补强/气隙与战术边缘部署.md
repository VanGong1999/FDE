# 气隙与战术边缘部署

> 整理自 Awesome FDE「Air-Gapped & Tactical Edge」。  
> 最难的前线工作发生在「互联网到不了」的地方：保密隔间、舰艇、前线基地、离线产线、强监管本地飞地。标准云剧本在此失效——你必须**把平台运进去**，而不是指着云说「连一下」。

---

## 1. 合规基石（先于写代码）

这些缩写决定架构选择：

| 概念 | 含义（简述） |
|------|----------------|
| **ATO** | Authority to Operate，授权官签字允许系统在其网络运行；常走 NIST RMF，可能 6–18 个月 |
| **DoD Impact Levels** | IL2～IL6，决定可用云与网络飞地（如 GCC High、GovCloud、NIPR/SIPR） |
| **FedRAMP** | 联邦民用对等；许多 GenAI 仅 Moderate——对国防负载可能是硬拦 |
| **STIG** | DISA 加固清单；CI 产物不合规往往过不了 ATO |
| **ITAR / EAR** | 出口管制；训练数据受控则权重本身也可能受控 |
| **CMMC 2.0** | 国防承包商认证；Level 2 实务底线常对齐 NIST SP 800-171 Rev.2 |

**发现阶段就要问清分级与认证路径**，不要第 12 周才发现。

## 2. 离线模型权重与包镜像

气隙主机无法 `pip install` / 拉 HuggingFace / 调公有 API。必须预置：

- **权重**：加密物理介质投递；到货 SHA-256 校验；优先 **safetensors**（避免 pickle RCE）  
- **许可证与溯源**：来源、协议、训练数据证明——「从 HF 下的」过不了审计  
- **内部镜像**：PyPI（devpi/bandersnatch）、npm（Verdaccio）、APT 等；`pip.conf`/`npmrc` 只指向内网  
- **CVE 扫描**：Trivy / Grype + 离线 NVD 快照，准入飞地前必须过  

---

## 3. 加固容器仓库

- **Iron Bank**（DoD 预加固镜像库）等客户指定源  
- **Harbor**：签名、复制、扫描  
- **Cosign** 签名 + Kyverno/OPA 拒绝未签名镜像  
- 优先 **distroless / chainguard** 基座（无可交互 shell 更难横向移动）  

---

## 4. 跨域与同步模式

- **单向二极管（Data Diode）**：物理单向（如权重进、遥测出）  
- **CDS（Cross-Domain Solution）**：跨密级调解；审批本身可能数月  
- **清单制同步**：进出物有签名清单、人工签核、不可篡改审计；禁止「后台偷偷同步」  
- **出境脱敏**：DLP（规则 + 分类器）清洗 PII/坐标/编制等后再到低侧

## 5. 边缘运行时

| 组件 | 用途 |
|------|------|
| K3s / MicroK8s / k0s | 轻量、可断网的 K8s |
| GKE on Bare Metal / Distributed Cloud | 客户机房内「类托管」K8s |
| Ollama / vLLM / llama.cpp / TensorRT-LLM | 本地推理开源权重（含 CPU/单卡） |
| Fluent Bit + 本地 WAL | 断网数小时仍可缓存，连通再转发 |

## 6. 气隙特有故障模式

| 故障 | 缓解 |
|------|------|
| 时钟漂移（无 NTP） | 第一天部署 Chrony/PTP |
| 证书轮换（无 Let’s Encrypt） | 飞地内建 PKI（Vault / step-ca） |
| 密钥（云 KMS 不可达） | Vault HA + HSM，或 SOPS+age |
|「首次启动」如何进配置 | 设计签名 sneakernet ISO；勿第 12 周才发现 |
