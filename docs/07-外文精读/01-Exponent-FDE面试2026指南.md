# 精读：Exponent《FDE 面试权威指南 2026》

> 原文语言：English  
> 精读日期：2026-09-22  
> 难度/受众：面试为主，兼交付认知  

## 精华摘要

Exponent 这篇 2026 指南把 Forward Deployed Engineer 面试定位为：**混合回路**——不是标准后端刷题流水线，而是工程能力、模糊问题拆解、客户判断，以及（在 AI 原生公司）生产级 LLM 系统判断的组合。

指南覆盖：角色是什么、多家公司的面试流程差异、各轮次（尤其是 Palantir 风格 Decomposition）、大量例题与答法框架、约 6 周备面节奏、薪酬区间与常见淘汰原因。核心信息是：**强工程师也会因为「一上来堆功能 / 无评测思维 / 不会推回」而被拒。**

对不同雇主，指南强调差异化准备：Palantir 偏编码 + 拆解 + Learning；OpenAI 等偏 Take-home、RAG/Eval、方案设计；Anthropic 相近角色强调安全、评测与可靠部署；此外还有 Databricks、Scale 等前线/平台变体。时间线上，AI 创业公司常见 3–4 周，大厂/Palantir/OpenAI/Anthropic 类常见 4–6 周（以招聘官为准）。

对本库读者：把本文当「地图」，把 [04-面试通关](../04-面试通关/面试全景与公司对照.md) 当「操练手册」；薪酬数字会过时，以最新公开数据与谈薪策略为准。

## 重点内容

### 1. 角色如何被定义（意译要点）

- FDE 嵌入客户，把平台/模型能力变成可运行工作流  
- 成功看业务结果与可复用性，不是只看代码合并  
- AI 时代额外要求：评测、护栏、成本延迟、人机回环  

### 2. 公司对照（精读提炼）

| 类型 | 指南强调的备面重心 |
|------|-------------------|
| Palantir FDSE | Decomposition、实用编码、Learning/陌生系统 |
| OpenAI FDE | 生产工程 + AI 判断 + 客户拆解 + 为自己作品辩护 |
| Anthropic Applied AI / FDE | 安全、Eval、受监管环境可靠部署 |
| 其他 AI/平台公司 | 视 JD：数据平台、国防/企业、垂直场景 |

### 3. 轮次共性

- Recruiter：动机是否真是 forward-deployed  
- 技术：编码或 Take-home 或系统设计（组合因公司而异）  
- Decomposition / 方案设计：先用户与结果  
- 行为/HM：ownership、失败、推回、使命  

### 4. Decomposition 为何「挂科率高」

指南与业界共识一致：候选人最常在第一分钟跳到产品形态。面试官买的是结构化过程。完整五步与练习见本库专篇精读与 [Decomposition 拆解面](../04-面试通关/Decomposition拆解面.md)。

### 5. 备面节奏（指南中的 6 周逻辑 → 本库落地）

- 先故事与拆解肌肉，再公司特化（算法 vs 项目）  
- 要有可演示、可辩护的作品（尤其 AI 公司）  
- 录音口述，沉默美化不算面试表现  

详见 [4–6 周备面计划](../04-面试通关/4-6周备面计划.md)。

### 6. 常见淘汰原因（意译归纳）

- 无用户/指标就谈模型与框架  
- Demo 思维，说不清如何知道系统有效  
- 只会答应客户，不会给选项式推回  
- 动机是「碰前沿模型」而非交付结果
