# 精读：各公司 Careers 岗位描述对照

> 原文：Palantir / OpenAI / Anthropic / Databricks 等公开 Careers 页  
> 精读日期：2026-09-22  
> 受众：投递前对齐 JD 语言与自我叙事  

## 精华摘要

官方 Careers 页很少给出完整面试题，但反复出现可迁移的**语言信号**：客户现场、模糊问题、端到端拥有、安全与可信、把能力产品化、跨职能协作。读 JD 的目的不是背使命宣言，而是：**用对方的动词改写你的简历子弹与面试故事**，并判断编码 vs 客户 vs AI 生产化的真实权重。

本篇把多家公开定位意译为对照表，并给出「简历动词替换」清单。岗位名会改（FDSE / FDE / Applied AI / Solutions），以描述段落为准。

## 重点内容

### 对照表（意译归纳）

| 公司/页 | 常见标题信号 | JD 反复词 | 你应准备的证据 |
|---------|--------------|-----------|----------------|
| Palantir | Forward Deployed Software Engineer | 客户问题、快速在复杂环境交付、ownership | 拆解+编码+学习速度故事 |
| OpenAI | Forward Deployed Engineer 等 | 企业部署、从发现到推广、与客户共建 | 生产形项目、eval、演示 |
| Anthropic | Applied AI / 相关 | 安全、可靠、有益部署、评测 | 护栏、HITL、失败分析 |
| Databricks | SAE/FDE/解决方案变体 | 湖仓、平台价值、客户成功技术向 | 数据栈+方案+工程 |

具体开口以当日 JD 为准；链接见文末。

### 如何读一篇 JD（步骤）

1. 标出 **频率最高的 10 个动词/名词**  
2. 标出 **出差/驻场/on-site** 要求  
3. 标出 **安全/合规/政府** 字样 → 提高护栏故事权重  
4. 标出 **编程语言与栈** → 决定刷题 vs 项目比  
5. 用这些词改一版简历项目描述（诚实，不虚构）  

### 简历子弹改写例

| 原表述 | 更 FDE 的表述 |
|--------|----------------|
| 负责后端接口开发 | 在客户约束下交付 X 集成，使 Y 指标从 A→B |
| 调优了 prompt | 建立 N 条黄金集与量规，将失败率从… |
| 做了 Demo | 带领试点通过门禁并完成培训交接 |
| 参与讨论需求 | 主持发现，输出书面问题陈述与非目标 |
