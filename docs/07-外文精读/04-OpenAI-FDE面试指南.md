# 精读：OpenAI FDE 面试指南

> 原文：The Forward Deployed — OpenAI FDE Interview Guide  
> 精读日期：2026-09-22  
> 受众：目标 OpenAI FDE / 强 Take-home 与生产 AI 判断的公司  

## 精华摘要

OpenAI 未公布统一 FDE 回路；该文基于公开报告（约 2026-07，**以招聘官为准**）。角色 JD 覆盖发现、技术定范围、设计、构建与生产推广，面试亦然：生产工程、AI 系统判断、客户拆解、以及**为你亲自交付过的作品辩护**。文中称**无确认的经典算法筛**——准备重心是构建与辩护，而非 LeetCode 题海。

高频结构：Recruiter → ~5h Take-home（OpenAI API）+ **录屏演示** → 技术深挖（Eval/RAG/微调权衡/护栏）→ 方案设计 → HM/价值观。强提交特征：评测、客户数据边界、成本与延迟诚实说明、短 rollout；演示质量按客户 Demo 标准。最难处常被总结为：**Evaluation + 客户优先开场**。

## 重点内容

### 回路一览

| 阶段 | 测什么 |
|------|--------|
| Recruiter | 是否真想做 forward-deployed，而非只想进 OpenAI |
| Take-home | 可运行工件 + 录屏；生产形完整度 |
| Deep dive | 如何知道系统有效；RAG/微调/护栏/慢请求调试 |
| Solution design | 开放客户简报；先范围后架构 |
| HM / Values | 客户面经历、歧义、失败、使命 |

公开描述约 7 个触点、3–4 周量级（报告差异存在）。

### Take-home 生产形清单（意译）

- 小而真的 API 功能（检索 / 小 Agent / Eval 架）  
- 标注评测集 + 指标  
- 可见的客户数据边界  
- 真实量级下的成本/延迟笔记  
- 基本日志/追踪  
- 一段 rollout 与采用衡量  
- 录屏：问题与结果开场 → 演示成功路径 → 决策与弃选方案 → 短而排练  

深挖轮会重访演示——每个决策要能辩护。

### 方案设计六步（意译）

1. 用户与业务结果、谁被衡量  
2. 选一个工作流而非整个部门  
3. **先定义 Eval**（集、指标、通过线）再构建  
4. 选能推动该指标的最窄第一刀  
5. 前置生产约束：延迟预算、单次成本、隐私合规、HITL 位置  
6. 此刻才素描架构，辩护**过线的最简方案**  

### 慢 LLM 工作流调试（意译）

复现并测量端到端 → 分阶段计时（输入/检索/拼装/模型/工具/后处理）→ 打主导成本（过大上下文、串行可并行、慢检索、大模型干小活）→ 先修主导项 → 对照延迟预算并跑 Eval 确认质量。

### 强弱示例（工单 AI）

- 弱：未明用户/指标就上 RAG+微调  
- 强：先问衡量（时长/分流/CSAT）→ 收窄到 tier-1 首响草稿 → 以坐席编辑量评测 → 数据边界与成本上限与 HITL → 再谈检索架构  

### 两周备面

- Week1：把 Take-home 做到含 Eval 与安全边界；口述设计题一律客户+Eval 开场  
- Week2：框架复练、计时录演示、准备歧义/失败故事；与招聘官确认真实回路
