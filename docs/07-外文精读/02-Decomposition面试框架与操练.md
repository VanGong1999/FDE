# 精读：Decomposition 面试框架与操练

> 原文：The Forward Deployed — FDE Decomposition Interview  
> 精读日期：2026-09-22  
> 受众：所有备 FDE/FDSE 面试者（必读）  

## 精华摘要

Decomposition 被作者称为 **FDE 标志性轮次、往往最重要的技术轮**：给你一个模糊、常常「伪装成解决方案」的问题，几乎不写代码，考察你如何端到端结构化。评分看过程——处理歧义、拆部件、是否持续出声。面试官只能评你说出口的话，**静默思考等于交白卷**。

文章给出严格顺序的 **五步（five moves）**，并强调几乎所有人的错误是**跳过 1–4 直接到第 5 步提方案**。面试官买的是前四步。文中用 Bad/Good/Great 对比开场两分钟，并给出三类探针（逼你补用户、逼你给具体物、逼你辩护硬点）。

另附「FDE 风味」例题（医院要 AI 书记员）、隐藏约束例题（安全手册问答），以及 **20 道无标准答案的练习题库** + 可粘贴到 AI 聊天的面试官协议。结论：这是表演技能，靠计时出声重复训练。

## 重点内容

### 五步框架（意译）

1. **点名用户与结果**：谁有问题、被什么结果衡量？瞄准结果不是功能。  
2. **大声说假设与范围**：包含什么、刻意搁置什么，并向面试官确认。  
3. **拆成 3–5 个子问题**：问题的部件，不是「调研→开发→上线」阶段。  
4. **找到硬点**：哪个子问题真正难、做错会毁掉结果；高手把时间花在这里。  
5. **提出具体第一步，并说出如何知道错了**：主动谈失败模式是 Senior 信号。  

### Bad / Good / Great（开场）

以「帮独居老人管药」为例（原文示例）：

- **Bad**：第一句就「做个提醒 App」——直接跳到形态，丢掉后续所有标尺。  
- **Good**：先问智能手机、药量、风险——有约束意识，但若问完仍回到预定 App，仍是在设计产品而非拆问题。  
- **Great**：先定义结果是「正确用药并保持独立」；拆成知晓方案、即时记得、安全失败（漏服/重复）；**硬点是安全失败**；围绕检测与阻止危险来设计，补药提醒是容易部分。  

### 探针与回收台词（意译要点）

当面试官说「结构说很久了，给点具体的」：这是测试不是不耐烦。应交付具体第一版，并解释为何先结构——因为硬点驱动整体设计；再说明如何验证。

当客户「就要某个功能」：可以一周验证该功能是否推动其真正指标，比三个月做出无需要逐行改正、反而增负的东西更便宜；**不是说不，是先对准数字**。

### 隐藏约束示例（安全手册）

工具若「等人来问」，可能服务的是本来就会查手册的谨慎员工；事故往往来自「自信却不再查」的老手。硬点可能是**让正确性进入作业计划/签核**，而不是做一个等人打开的 Chatbot。先用发现验证事故来源再决定是否简单 Q&A。

### Rep Kit 用法

- 五分钟、出声、录音  
- 用文首五步自检 PASS/FAIL，引用自己的原话当证据  
- 初练常挂至少两项——评分要狠  
- 可用原文 AI interviewer 协议对抗练习
