# FDE 知识库 Docsify 视觉升级设计

## 意图

把当前以 Markdown + Docsify 为核心的 FDE 知识库，升级为更像完整学习产品的 GitHub Pages 前端：入口更有记忆点，目录更容易浏览，正文阅读更舒适，移动端也能正常使用，同时保留现有课程内容与 Markdown 工作流。

## 成功标准

- 首页能快速说明“这是给谁的、能学到什么、从哪里开始”。
- 所有现有课程入口仍可从侧栏或首页到达，搜索、分页、Mermaid、KaTeX 和图片能力不回退。
- 每个 Markdown 页面的第一行一级标题继续作为正文主标题，不用 JavaScript 重写正文标题。
- 首页、侧栏、内容区和移动端形成统一视觉系统，而不是只换一组颜色。
- 纯静态部署即可运行，不新增构建服务、后端或运行时数据依赖。

## 不做的事

- 不重写或批量改动课程 Markdown 内容。
- 不把 Docsify 替换成 React/Vue 单页应用。
- 不引入登录、评论、用户数据或需要密钥的功能。
- 不覆盖工作区当前已有的课程内容改动。

## 约束

- 部署目标是 GitHub Pages。
- 现有入口为 `index.html`，内容入口为 `README.md`，目录来自 `_sidebar.md` 和 `_coverpage.md`。
- 现有第三方脚本通过 CDN 加载，增强逻辑应使用原生浏览器 API。
- 本轮只修改前端入口、主题样式、封面/首页呈现和必要的前端脚本。

## 方案比较

### 方案 A：深度升级 Docsify（采用）

保留 Docsify 的路由、Markdown 渲染和插件生态，重做主题层，并在入口增加轻量增强：统一品牌头部、首页学习路径区、阅读进度、返回顶部、主题切换、当前章节状态和更完整的移动端菜单体验。优点是兼容现有仓库、变更集中、GitHub Pages 风险最低；代价是仍受 Docsify DOM 结构约束。

### 方案 B：只做 CSS 改造

只调整色彩、排版、卡片、边框、表格和响应式。实现简单且风险最低，但无法把首页和阅读流程提升为完整的学习操作台。

### 方案 C：重做独立前端应用

用自定义路由和组件重新实现首页、搜索和文档阅读。自由度最高，但要重新解决 Markdown 加载、锚点、目录、搜索、分页和部署兼容性，和当前内容型仓库不匹配。

## 采用方案的具体设计

### 视觉系统

- 基调：深色墨蓝作为品牌锚点，荧光青绿作为操作色，浅灰蓝作为阅读背景。
- 字体：中文无衬线正文 + 更有识别度的标题字体；代码使用等宽字体。
- 组件：玻璃感侧栏、分层卡片、细边框、柔和阴影、状态标签、渐变高光和清晰的 hover/focus 状态。
- 动效：只使用短时、低干扰的淡入/位移，尊重 `prefers-reduced-motion`。

### 页面层级

- 封面：保留标题与副标题，但增加学习定位、核心能力标签、入口按钮和目录导向。
- 首页：把现有 README 中的正文第一行一级标题作为页面标题，重点突出“开始学习”“四周路径”“知识库分区”“工具箱/面试”等入口。
- 内容页：保留 Markdown 原始层级，用更强的标题层级、引用块、表格、代码块、图片、Mermaid 容器和上下页导航区分信息密度。
- 侧栏：强化品牌区、搜索区、章节分组、当前项、滚动区域和移动端展开行为。

### 轻量交互

- 首页根据现有内容提供可见的学习入口和知识库统计，不依赖后端。
- 内容页显示阅读进度并提供返回顶部入口。
- 提供主题明暗切换，并使用本地存储记住用户选择。
- 给外部链接增加清晰的视觉区分；增加键盘 focus 样式和基础可访问性。

## 需要 builder 决定的细节

- 具体色值、断点、阴影和动效参数。
- 首页增强区是否完全通过现有 README HTML/CSS 表达，还是由入口脚本补充少量结构。
- 不改变正文内容前提下，哪些首页视觉数据可以从现有 DOM 或导航中自动统计。

## 验证方式

- 静态检查 `index.html`、`assets/custom.css` 和首页 HTML 结构。
- 启动本地静态服务器，验证首页、至少两个深层 Markdown 页面、搜索、侧栏、分页、Mermaid/KaTeX 与移动端布局。
- 检查 Git diff，确认没有批量改写课程内容和未授权覆盖已有改动。
