# Day 1 · 成为 AI FDE 所需的技能、工具与经验

一句话总结：把三大技能拆到细粒度并映射到周，再把「真实商业问题 + 客户合作」两类经验落到可执行的求职行动上，并用招聘数据验证这套框架。

## 三大技能细分（每项对应一周）

### 1. AI Engineering（Week 1）
技能：选择正确模型、agent frameworks、ADLC、开源模型、本地模型、context engineering、**harness engineering** 等。

**技术栈**：LangChain、Claude Code、Claude Agent SDK。

### 2. AI Architecture（Week 2）
技能：evals、observability、agentic RAG、memory、MCP、durable state、agent swarms、self-improvement（乃至 recursive self-improvement）。

**技术栈**：LangGraph、LangFuse。

### 3. Forward Deployed Engineering（Week 3）
技能（商业 + 技术混合，偏 senior）：
- 商业：customer discovery（客户发现）、operational handover（运营交接）、adoption（采纳）。
- 技术：API 与 MCP gateways、enterprise context layer、production deployment、cloud infrastructure。

**技术栈**：AWS Agent Core 等云部署平台。

## 两类实践经验（如何获取）

### 经验 1：解决真实商业问题
- **最优**：为客户或当前雇主交付真实 LLM/agent 项目（尤其 agentic RAG 项目，简历上很亮眼）。
- **次优**：自己业余时间构建一个解决真实商业问题的项目，放 GitHub、发 LinkedIn 提升曝光。
  - 建议在课程项目上「改造、个性化」，应用到稍微不同的业务领域，加入个人见解。
  - 发帖时描述做了什么、个人洞察与 takeaways、如何走出自己的方向。
  - 可 **tag 讲师**，讲师会来评论帮忙放大曝光（可见度 → 未来客户/雇主）。

### 经验 2：客户合作（内部或外部）
- **不一定要是 AI 项目**，任何与客户合作、能展示 partnership 的经历都算。
- 几乎任何公司都能找到接触最终客户的机会，AI 或非 AI 都行，重点是证明「能与用户直接协作」。

## 招聘数据验证（关键数字）

讲师调研了 **184 家雇主、316 个职位**：

| 要求项 | 占比 |
|--------|------|
| 需要 AI Engineering | **88%** |
| 需要 AI Architecture | **79%** |
| 需要 Forward Deployed Engineering | **95%**（其余 5% 虽未明说但同属该领域） |
| 需要解决真实商业问题 | **88%** |
| 需要交付给最终/内部客户 | **78%** |

- **41%**（近一半）的职位**五类全部都要**；**48%** 至少需要四类；仅约 **10%** 需要两到三类。
- 结论：这套「3 技能 + 2 经验」框架**广泛覆盖**了 FDE 岗位的招聘要求。
