# Day 2 · 探索 UnderCover 理赔数据与处理人决策

一句话总结：用 LLM 之前先吃透数据——25 条理赔、50 份政策文档、6 类理赔、3 档难度，labels 是人工专家的 ground truth；数据里还埋了「复活节彩蛋」。

## 数据结构

- **25 条示例理赔**（travel insurance claims）+ 每条对应的**人工决策（labels）**。
- **50 份政策文档**（约 1000+ 词的政策文本）。
- 数据由 `get_sample_data()` 加载，参数：
  - `tiny=True` → 只取 **5 条**（最省钱）；`tiny=False` → 取 **25 条**。
  - `held_out=True` → 取**完全独立的数据集**，用于评测（不在构建时使用）。

### 单条数据点字段
`claim_id`、`customer number`、`type`（如 trip delay）、故事描述（story）、items、receipts、`status`（open）。

### Labels（ground truth）
- 每条记录人工专家的决策 + 赔付金额 + 理由（rationale）。
- 例：航班被取消、索赔 $420 → 决策 **approve**、全额赔付 **$420**。

## 六类理赔（claim types）

1. Trip delay（行程延误）
2. Baggage lost（行李丢失）
3. Medical emergency（医疗急救）
4. Baggage delayed（行李延误）
5. Passport（护照）
6. Trip cancellation（行程取消）
7. Trip interruption（行程中断）

> 注：转写稿里「6 类/7 类」略有出入，实际列出的类型是上述 7 种。

## 难度分级（difficulty）

| 难度 | 数量 | 含义 |
|------|------|------|
| Routine（常规） | **15** | 按政策就能答 |
| Hard（难） | **5** | 政策解读较复杂 |
| Manual（人工） | **5** | 需**公司手册**（manual）才能答对，本阶段不给 LLM 这份手册 |

- 后 5 条「manual」在拿到手册前**不可能答对**（后续周会拿到手册）。

## 数据洞察（讲师点出的有趣发现）

- **专家只在「routine（简单）」案例上才敢 decline**；一旦是 hard 或 manual，他们只会 approve 或 refer，**不敢在更微妙的案例上拒绝**。

## 复活节彩蛋（合成数据里的梗）

- **Claim 1015**：从巴黎飞回家后才发现把 8 岁儿子 Kevin 留在家（《小鬼当家 Home Alone》梗）→ 正确答案是 **decline**（把孩子独自留在家不能理赔）。
- **另一条**：拉斯维加斯单身派对上醒来发现缺了颗门牙、失忆（《宿醉 Hangover》梗）→ 紧急牙科治疗。

## 方法论要点

- **动 LLM 之前先彻底理解并可视化数据**（best practice，很多人跳过）。
- 数据是合成的（讲师用 Claude Code / Opus 5.5 生成），但要**当作真实客户数据**来角色扮演。
- 可视化用 pandas DataFrame：按类型、难度、决策分布做图表。
- 代码里非 AI 部分（可视化函数）不必逐行理解，当作「从 Stack Overflow 抄来的 cookbook 函数」即可。
