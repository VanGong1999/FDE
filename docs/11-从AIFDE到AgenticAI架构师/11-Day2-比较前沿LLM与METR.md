# Day 2 · 比较前沿 LLM：Artificial Analysis、帕累托前沿与 METR

一句话总结：用 artificialanalysis.ai 建立模型选择的「第一直觉」，用帕累托前沿理解智能/成本权衡，再用 METR 的「人力小时」指标看 agent harness 的加速曲线——但最终判断永远回到自己的业务任务。

## Artificial Analysis（artificialanalysis.ai）

- 做基准测试（benchmarking）的公司，用大量测验测 LLM。
- 定位：**benchmark 要「大打折扣」（a heavy pinch of salt）**，但作为「建立第一直觉」很有用。
- 建议：**收藏该网站**（虽然没人再用书签了）。

### Blended Intelligence Index（混合智能指数）
- 单一「AI 智能指数」，描述模型多聪明。
- 时间轴：x 轴为各模型发布日期，不同颜色代表不同厂商（OpenAI 黑、Anthropic 铁锈棕、Gemini 绿）。
- 追溯到 ChatGPT 发布（约 4 年前）。
- **每几个月要重新发明更难的指标**（因为模型在旧指标上已经 99.9% 封顶），并**回溯重测旧模型**——所以 2022/2023 的模型在今天指标下基本都得 0 分。

### 讲师对智能曲线的判断（两条 S 曲线）
- 不是一条曲线，而是**两个 bump / 两条 S 曲线**：
  1. **Pre-training Scaling（预训练缩放）**：模型越做越大、数据越训越多（Chinchilla scaling laws：翻倍参数 + 翻倍数据），顶点是 **GPT-4.0（约 2024 中后期）**。
  2. **Post-training + Inference（后训练 + 推理）**：主要是 **RLVR（带可验证奖励的强化学习）**，让模型在回答前「思考」→ 产出更强的结果（Opus 5.5、Fable 5.1、GPT-6、Astra 等）。
- **预测**：针对这类指标，未来 ~6 个月可能开始**平台期（plateau）**，除非再出现新突破。

### 当前模型强度榜（课程当时）
- 最强：**Claude Opus 5.5** → 其次 **Claude Fable 5.1** → 再 **GPT-6 Astra**（OpenAI）→ **Muse Spark**（Meta）→ **Grok 4.7**（xAI，Grok 4.8 刚出）→ 开源系 **GLM5.3 / Qwen3.8 / Mimo2.6 / Kimi K3**。
- 智能/速度/成本三榜头名：**Opus 5.5 最聪明**、**Gemini 3.8 Flash 最快**、**GPT-6 Luna 最便宜**（便宜到比很多开源模型还低）。

### 帕累托前沿（Pareto Front / Pareto Frontier）
- 散点图：x 轴 = 成本（对数坐标，向右按倍数涨），y 轴 = 智能。
- 目标象限：**左上角 = 又聪明又便宜**。
- 虚线 = **Pareto Front**：在给定预算（x 轴）下能拿到的最聪明模型的最优权衡线。
- 建议：**尽量选 Pareto Front 上的模型**；前沿实验室都在争抢这条线上的位置（OpenAI 力推 Luna 上这条线）。
- 但 Pareto Front **不是真理**：智能指数只是指示性的，最终要按自己的业务任务测。

## 模型选择方法（核心）

1. 用 benchmark 做**第一轮筛选**，选出候选模型。
2. 再针对**自己的业务任务**做实际实验：测性能 vs 商业目标。
3. 同时看**非功能需求（non-functionals）**里的速度与成本。
4. 判断方式：`smart / fast / cost` 三维权衡，今天 Lab 就是干这个。

## METR（metr.org）

- 独立 AI 安全公司，研究「agent 到底变得多聪明」。

### 测试设计（天才之举）
- 取一组合软件工程任务（爬网站并绕过反爬、利用漏洞、找复杂 bug…）。
- **任务难度 = 人类专家平均要花多少小时解决**（用「人力小时」度量难度）。
- 图表：x 轴 = 时间（自 GPT-2 发布），y 轴 = 模型能解决的任务所需「人力小时」。
  - 例：**Claude Opus 4.6 落在约 12 小时**（能解决人类需 12 小时的任务）。

### 关键细节
- 统计口径：**LLM 至少 50% 概率能解决**的任务（允许 50% 错）；另有 80% 口径的图表。
- 为什么 50% 也够用：这些任务**可验证（verifiable）**，可并行跑多个（如 10 个），只要有一个解决就行——10 个各 50% 成功率 → 至少一个成功的概率约 **99.9%**。
- METR 不关心成本与耗时，只关心「能不能解、难度多大」。

### 与 Artificial Analysis 的本质区别
- METR 还测了 **harness（围绕 LLM 的脚手架）**——让 LLM 从「生成内容」到「能分析、探索、解决问题、独立工作」。这是接下来三周的大主题。

### 令人警惕的结论
- 这条曲线**增速越来越快**，甚至**比指数还快**（log 图仍向上弯 = 快于指数增长）。
- 强到「**跑出图表**」：Claude Mythos / Claude Fable（更安全版）强到 METR 已没有能自信给出、且测过人类等效时长的任务（现有设置扛不住要跑几天的任务）。
- 讲师预测：这不是纯指数增长，更多是 harness 改进带来的超常收益，但**随着 harness 变强、模型独立工作更久，曲线会继续上升**。

### 收束（冷静一下）
- 这只适用于**软件工程/编码任务**（可验证：测试过没过、问题解没解）。
- 现实很多任务**不易直接度量**：PowerPoint 好不好？策略好不好？商业想法成不成立？
- 这些任务未必适合 agent 框架，大概率走 Artificial Analysis 那种曲线、趋于平台期。
