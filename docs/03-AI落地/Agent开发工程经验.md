# Agent 开发工程经验

从 Pi / Hermes / OpenClaw / Codex / Claude Code 等开源 Harness 对照，以及上下文压缩、安全隔离、子代理编排等实践中抽出的**可落地工程经验**。偏「怎么造系统」，不是框架品牌巡礼。

> 开源对照总表见 [32-Agent-Harness开源实践对照](../10-概念课程/02-检索与Agent/32-Agent-Harness开源实践对照.md)。概念分拆见 07/08/09/11/13/16/23。原始笔记：[pictures/notes.md](../../pictures/notes.md)。

## 1. 先钉死：Agent 就是一个循环

### 1.1 循环本体

所有编码 Agent 的内核都是同一件事，只是函数名不同：

| 项目 | 循环名字（量级感） |
|------|-------------------|
| Pi | `runLoop`（薄，约百行级） |
| Hermes | `run_conversation`（厚，可达数千行） |
| Codex | `run_turn` |
| Claude Code | `query()`（闭源） |

**一圈在干什么：**

1. 调模型，流式拿到助手消息 + `stopReason`  
2. 从消息里筛出 `tool_call`  
3. 有工具 → 执行 → 把结果追加进消息列表  
4. 无工具 → 收尾；有工具 → 再进下一圈  

口条：**stream → find tool calls → run → append → repeat。**

消息列表就是记忆：系统 / 用户 / 助手 / 工具结果按顺序堆叠。工具输出是观察（observation），不是「人类又说了一句」。

### 1.2 为什么成本会炸

一回合 = **调用 + 执行 + 追加**。第 N 回合会重放第 1…N−1 的历史 → **输入 token 近似二次增长**。不压上下文，长任务一定又贵又慢。

### 1.3 工程清单

- [ ] 循环有明确退出：无工具调用 / 达最大迭代 / 熔断（费用、步数、重复检测）  
- [ ] `stopReason` 为 error / aborted 时有分支，不静默当成功  
- [ ] 每圈结束前，工具调用与工具结果在协议上成对（见 §8）

## 2. 工具：招聘启事 + 操作槽

### 2.1 模型只看见「招聘启事」

工具对模型只有：`name` / `label` / `description` / 参数 schema。真实代码在幕布之后——模型填参，运行时执行。

描述写糊，模型就会乱调；描述写清「何时用、何时不用、失败返回什么」，本身就是提示词工程。

### 2.2 两类工具，一种形态

| 类别 | 含义 |
|------|------|
| 预置工具 | harness 出厂：读、写、编辑、bash、grep、find、ls… |
| 外部工具 | 设计时 / 运行时接入（含 MCP），**形态应与预置一致** |

Pi 的经验：核心约七个内置动词；MCP 作为对等插件接入，不另起一套协议。

### 2.3 把「在哪跑」从「做什么」解耦

同一套工具定义，通过操作槽（如 `BashOperations`）插到不同执行位置：

| 位置 | 典型工厂 | 用途 |
|------|----------|------|
| 本地 | `createLocalBashOperations` | 本机磁盘子进程 |
| SSH / 远程 | `createRemoteBashOperations` | 路径转换 + 网络隔离 |
| OS 沙箱 | `createSandboxedBashOps` | jail / 受限容器 |

上层 Agent 循环不改；换环境只换槽的实现。

### 2.4 工程清单

- [ ] 工具 schema 严格校验；禁止 `shell(any)` / `sql_raw(any)` 类万能工具  
- [ ] 预置与 MCP 走同一 Tool 接口  
- [ ] 执行位置可配置（本地 / 远程 / 沙箱），业务逻辑不绑死本机路径

## 3. 安全：Gate + Jail，缺一不可

### 3.1 两层防御

| 层 | 机制 | 降低什么 |
|----|------|----------|
| **Permission Gate（许可门）** | 解析工具参数、对照策略、可人工确认 | 危险事件**发生频率** |
| **Sandbox / Jail（沙箱）** | 受限容器、无外网、副本而非原文件、配额 | 漏网动作的**破坏上限** |

口条：**网关管能不能放行；沙箱管出事能坏多大。**  
许可门会漏（人会疲劳、模型输出快）；沙箱兜住爆炸半径。最坏情况要设计到可接受（例如单目录乱掉 + git 可恢复）。

许可门三种结果：**Allow / Ask / Deny**。安全工具（读、搜）可自动跑；危险工具（编辑、写、bash）先敲门。

### 3.2 Path Jail（更早、更轻）

所有文件路径先 `realpath`，必须落在 workdir 内，否则直接 `PermissionError`——在策略校验前就挡住 `../` 逃逸。Agent 主循环把异常包装成工具错误返回模型即可。

```python
root = os.path.realpath(workdir)

def resolve(path: str) -> str:
    full = os.path.realpath(os.path.join(root, path))
    if full != root and not full.startswith(root + os.sep):
        raise PermissionError(f"{path!r} escapes the working directory")
    return full
```

### 3.3 企业向：四套集合交叉才允许

工具调用要同时落在：

1. 用户权限（用户 / 组 / 角色）  
2. 已签名的代理能力清单  
3. 管理员锁定的策略  
4. 资源 ACL  

且宜**实时解析**，不要会话开始一次性钉死。口条：每个 harness 都应自带沙箱；写操作的授权要可审计。

### 3.4 工程清单

- [ ] Gate 与 Jail 都写进 SOW，不只靠「请勿执行危险命令」  
- [ ] 路径逃逸有代码级早拦  
- [ ] 高危动作有 HITL（Ask），且有 Deny 时给模型可消化的原因  
- [ ] 验收：故意让模型读 secret / 出网 / `../etc`，应失败

## 4. 上下文：Loop 压缩是刚需

### 4.1 三种「留什么」

同一问题——窗口有限——三种答案：

| 策略 | 保留什么 | 典型场景 |
|------|----------|----------|
| 压缩 | **结构化摘要** | 长会话继续聊 |
| 交接 / 接力 | **蒸馏后的目标** | 开干净新会话 |
| 子代理 | **仅最终答案** | 探索成本关在子进程 |

### 4.2 头中尾原则

- **头**：系统提示 + 最早若干消息，保护住  
- **尾**：最近内容逐词保留（例：约 20% 触发量，或固定 keepRecentTokens≈20k）  
- **中**：才做总结（昂贵的一步）  

Hermes 口条：**四个廉价步骤，围绕一个昂贵步骤**——处理旧工具结果（免费）→ 保护头 → 保护尾 → **总结中部** → 重复更新摘要。

### 4.3 触发哲学：调用前 vs 调用后

| 流派 | 做法 | 代表感 |
|------|------|--------|
| 调用前检查 | 绝不发送超预算请求 | Hermes / Codex |
| 调用后恢复 | 先跑，溢出再压 | Pi |

Pi：固定预留 **16384** 给回复（`contextTokens > window - 16384` 才压）。  
Hermes：按有效窗口**比例**预留，再加边界修正（保底 64k、小窗阈值≥75%、冲突用 85%）。

```python
effective_window = context_length - (max_tokens or 0)
# 阈值默认约 50%；floored = max(pct, 64000)
# 若 floored >= effective_window → 改用约 85%
```

节奏对比：Pi 接近阈值时**一次长暂停**；Hermes 可开**微压缩**（多次短暂停，账单分期付）。

### 4.4 Token 怎么估

- 优先用服务商返回的精确 usage（Hermes：信服务商，不信自己猜）  
- 尾部尚无 usage：字符数÷4；工具计 name+JSON；图片可固定估算字符  
- 估算故意偏高 → **偏早压缩**，好过撑爆  

截断合法性：不是每个合法切点都开启新轮次；user 常开启轮次，assistant / toolResult 往往是轮次中部——压缩逻辑要分清这两个问题。

### 4.5 摘要应结构化

Pi 约 6 段（目标、约束、进度、关键决策、下一步、关键上下文）。  
Hermes 固定 **11 段**（含历史任务快照、活跃状态、阻塞项、已解决问题、相关文件、已裁剪技能等）；关键上下文**永不写 [REDACTED]**。

压缩失败策略：floor（系统提示/工具 schema 不可总结）→ two strikes → cooldown（限流等待）→ fallback（辅模型→主模型→无模型摘要）。口条：**压缩允许失败，绝不允许死循环。**

### 4.6 工程清单

- [ ] 先定「留摘要 / 留目标 / 留答案」，再定阈值数字  
- [ ] 输出预留（max_tokens）从有效窗口里扣掉  
- [ ] 摘要用固定标题结构，便于下游消费  
- [ ] 压缩失败有降级，主循环不卡死

## 5. 提示与技能：组装生成，按需付费

### 5.1 系统提示是组装出来的，不是硬编码

每次调用可按序拼：

1. 基础模板（身份 + 工具列表）  
2. 追加 / 客户可替换段  
3. 向上 walk 到的 `AGENTS.md` / `CLAUDE.md`（全局先加载，**最近者最后生效**）  
4. 可用技能：名称 + 描述 + 位置  
5. 当前日期 + cwd（常依赖读工具可用）  

硬编码部分应极小（一行身份 + 工具列表 + 少量准则）；身份来自「周围真实世界」的每次组装，才不容易过时。

### 5.2 SKILL.md：三批付费

| 批次 | 内容 | 何时进上下文 |
|------|------|--------------|
| 1 | name + description（frontmatter） | 启动即加载，几乎无正文成本 |
| 2 | SKILL.md 正文 | 技能被触发时 |
| 3 | reference / examples / scripts | 打开具体文件时 |

口条：Claude（及同类）**分三批为技能付费，通常在第一批就停**。正文建议 ≤500 行；复杂内容拆文件。

注意指令语义：

- `run analyze_form.py` → 执行，只拿输出（省上下文）  
- `see analyze_form.py for the algorithm` → 读源码进上下文  

自由度：窄桥（给精确脚本勿改）vs 旷野（给目标让模型选路径）——按风险选。

### 5.3 校验闭环

改 → 立刻验证 → 修 → **通过才继续**。批量改动可先产出计划文件，脚本校验计划后再动真格。口条：**会做验证的循环，胜过只寄希望于单条指令。**

经验可 `/learn` 落成新 `SKILL.md`（描述宜短，如 ≤60 字符），让一次好会话变成可复用资产。

### 5.4 工程清单

- [ ] `AGENTS.md` 发现顺序写清（全局 → 向上 walk → 最近覆盖）  
- [ ] 技能元数据与正文分层加载  
- [ ] 改文件后有可重复跑的 validator（脚本或规范自查）

## 6. 记忆：谁写、写哪、何时剪

### 6.1 三种形态（复杂度递增）

| 层级 | 形态 | 谁写入 | 特点 |
|------|------|--------|------|
| Pi | 人维护的 `AGENTS.md` 等 | **人** | 最不容易出错 |
| Hermes | `MEMORY.md`（工作）+ `USER.md`（人物） | **代理**每轮后复盘 | 工作状态更全 |
| OpenClaw | 更多文件（含 daily / dreams 等）+ 扫描晋升 | 代理写 + **后台扫描**保留 | 召回强，最需调优 |

口条：文件越多，事实可放位置越多，**优先级规则也越多**；差异常在「谁被信任执行写入」。

Hermes 细节：条目用 `§` 分隔可跨多行；记忆工具 = 添加 / 用唯一短子串替换 / 删除（无需跟踪 id）；回合结束后台 fork 复盘，**不碰对话提示缓存**。

### 6.2 生命周期

建议节奏：7 天复盘 → 30 天标陈旧 → 90 天归档。口条：**从不裁剪的记忆，会变成始终被加载的噪声。**

### 6.3 工程清单

- [ ] 写清记忆文件职责与优先级  
- [ ] 默认少写；有过期与删除路径  
- [ ] 真源（CRM/DB）优先于记忆；冲突时纠正记忆

## 7. 子 Agent：边界决定能碰什么

### 7.1 对照总表（选型背这张）

| 对比项 | Pi | Hermes | Codex | Claude Code |
|--------|----|--------|-------|-------------|
| 模型侧工具 | `subagent`（单/并/链） | `delegate_task` | `spawn_agent` 等一套 | `Agent` + SendMessage / TaskStop |
| 是否核心 | 否（示例扩展） | 是 | 是 | 是 |
| 本质 | **独立 OS 进程** | 同进程**线程** + ContextVar | 进程内**子会话** | 独立上下文；可选独立 **git worktree** |
| 定义位置 | `~/.pi/agent/agents/*.md`、`.pi/agents/*.md` | leaf / orchestrator 枚举 | 配置层 `[agents.<name>]` | `.claude/agents/*.md` 大 frontmatter |
| 启动装载 | 空上下文 + 角色提示 | 空上下文 + 自动 brief | 空或 fork 近 N 轮 | 空 + CLAUDE.md + git 快照 |
| 子工具更少？ | 是（`tools:`） | 否（减五工具黑名单） | 否 | 是（tools / disallowedTools） |
| 并发 | 同时 4，单次最多 8 | 3 | 每会话 4 | 20，会话最多 200 |
| 嵌套 | 扩展未设上限 | 1 | v1=1；v2 slot 限 | 3 |
| 默认姿态 | **阻塞**父级 | **后台** | `wait_agent` | **后台** |
| 超时 | 无 | 心跳过期 | 默认 30s～1h | 文档未必写清 |
| 重启存活 | 否 | 是（SQLite 投递） | 是（rollout 水化） | 可按 agentId 恢复 |
| 观察方式 | 流式进父级 tool card | `tail -f` 子日志 | 事件转发 | Agent view |

**你选的边界，决定了子进程能访问什么。** 同一地址空间（线程/子会话）必须手动补隔离。

### 7.2 三种委托模式

| 模式 | 行为 |
|------|------|
| single | 委托一次，一个答案返回 |
| parallel | 一次扇出多任务再汇合 |
| chain | 管道传递 `{previous}` |

### 7.3 Recipe 与角色

角色 = YAML（name / description / tools / model）+ Markdown 正文 = systemPrompt。  
例：`implement` = scout（廉价只读）→ planner → worker（强模型全工具）；各角色**独立进程**，上下文不自动共享，只传上一步结果。父进程只看见最终结果，探索成本关在子进程内。

任务过大时的规模答案：隔离子进程只返答案；交接开干净会话只带目标；编排器驱动 N 实例（实验性，跨机 fleet）。

答案回传是**接缝**：子代理输出成为父输入——值得扫描 / 审批 / 标记，而不是无脑拼接。

### 7.4 工程清单

- [ ] 先画 recipe 图，再选框架  
- [ ] 子角色工具集默认收缩  
- [ ] 明确阻塞 vs 后台、超时、是否跨重启  
- [ ] 父子交接格式固定（JSON / 固定标题摘要），禁止散文传话

## 8. 可靠性：成对落盘与可回滚

### 8.1 外套寄存式崩溃（coat-check）

规则：**每一次工具调用，必须恰好收到一条结果。**

若在「发出 tool_call」与「写入 tool_result」之间崩溃，日志末尾留下**无人兑现的票据** → 后端校验拒收整段会话 → 朴素 resume 首请求即失败。

落盘与恢复协议必须处理 unredeemed ticket（补伪造失败结果 / 截断非法尾 / 人工修复），不能假装会话完好。

### 8.2 进程结束后磁盘上有什么

| 系统 | 落盘形态 |
|------|----------|
| Pi | 每会话一个 JSONL（条目序列） |
| Hermes | `state.db`（每消息一行） |
| Codex | 带时间戳的记录文件 + DB 作缓存 |
| Claude Code | 每会话 ID 一个 JSONL（内部格式可能变） |

### 8.3 Checkpoint / Undo 边界

| 系统 | 要点 |
|------|------|
| Pi | 无影子仓库、无 `/undo` |
| Hermes | 影子 Git（隔离 `GIT_DIR`），用户 `/rollback` |
| Codex | 文件级 undo 已移除；对话层回滚 |
| Claude Code | 每用户提示前 checkpoint；**bash 变更与子代理编辑常不追踪** |

口条：**快照不能替代 Git。**

### 8.4 工程清单

- [ ] tool_call / tool_result 事务性写入或崩溃恢复脚本  
- [ ] 明确 undo 覆盖范围（不含 bash / 子代理则写进用户文档）  
- [ ] 会话可导出、可审计、可按租户隔离

## 9. 一条推荐装配顺序（从薄到厚）

1. **跑通循环** + 严格工具 schema + 路径 jail  
2. **许可门**（Allow/Ask/Deny）+ 最小沙箱  
3. **上下文预算**：输出预留 + 头中尾压缩（先调用前检查更稳）  
4. **AGENTS.md / SKILL** 组装与按需加载  
5. **结构化摘要** + 压缩失败降级  
6. **记忆文件**（先人写，再考虑代理写）  
7. **子 Agent / Recipe**（先 chain 固定流水线，再 parallel）  
8. **成对落盘 + checkpoint 边界说明**  
9. 需要网关化时再引入 OpenClaw 式「harness 插件化」

中间层行数不是成绩：薄循环清晰但缺企业能力；厚循环能力全但难审计。按客户威胁模型选厚度。

## 10. FDE / 面试速用

**60 秒：**  
「Agent 工程就是循环、工具槽、压缩、安全与子代理。工具对模型是招聘启事，执行用操作槽换本地/远程/沙箱。安全靠 Gate 降概率、Jail 限爆炸半径。窗口有限时压缩留摘要、交接留目标、子代理只留答案。子进程边界决定能访问什么；工具调用必须与结果成对落盘。」

**客户现场先问：**

1. 最坏情况坏多大？Gate+Jail 是否都有？  
2. 长任务怎么压窗口？留的是摘要、目标还是答案？  
3. 多角色是固定 recipe 还是自由社团？  
4. 崩溃恢复能否处理半截 tool_call？  
5. 记忆谁写、写哪、多久剪？
