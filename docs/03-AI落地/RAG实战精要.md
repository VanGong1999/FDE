# RAG 实战精要

**RAG（Retrieval-Augmented Generation）** 用检索到的证据约束生成，是企业落地最常见的主路径。本篇按「能上线」标准讲链路、选型、失败模式与验收。

---

## 1. 最小链路

```mermaid
flowchart LR
  Q[用户问题]
  A[鉴权与改写]
  R[检索]
  RR[重排可选]
  C[组装上下文]
  G[生成带引用]
  V[校验与护栏]
  Q --> A --> R --> RR --> C --> G --> V
```

同步你要建设的资产：

- 文档语料与版本  
- 切片与嵌入索引  
- 元数据（权限、时间、来源、产品线）  
- 评测集  

---

## 2. 切片（Chunking）

| 策略 | 适用 | 注意 |
|------|------|------|
| 固定长度 + 重叠 | 通用起步 | 可能切断表格/条款 |
| 按标题/段落结构 | 手册、制度 | 需良好文档结构 |
| 按语义 | 杂乱语料 | 实现复杂 |
| 按对象（一条款、一工单） | 合同、工单 | 往往最好 |

实践建议：

- 元数据写入每块：`doc_id, section, acl_tags, updated_at`  
- 表格尽量保留为整块或转成可读文本  
- 版本更新要能**重建或增量更新**索引  

---

## 3. 检索与重排

| 手段 | 作用 |
|------|------|
| 向量检索 | 语义相似 |
| 关键词/BM25 | 专有名词、编号、精确匹配 |
| 混合检索 | 企业场景默认值得试 |
| 元数据过滤 | **权限与范围**先滤再搜 |
| Rerank | 提升 top-k 质量，换延迟/成本 |

**权限必须在检索层强制执行**，不能只靠「提示模型别看」。

---

## 4. 组装与生成

好的提示结构通常包括：

1. 角色与任务边界（只能基于证据）  
2. 引用格式要求  
3. 证据不足时的拒答策略  
4. 用户问题  
5. 检索片段（带编号与来源）  

输出建议强制：

- 答案  
- 引用列表（可点击回源）  
- 置信/是否证据不足  

---

## 5. 失败模式诊断表

| 现象 | 可能原因 | 动作 |
|------|----------|------|
| 胡编 | 未拒答；上下文不够；指令弱 | 加强 grounding；无证据则拒 |
| 答非所问 | 检索错；问题未改写 | 混合检索；查询改写；扩大/缩小 k |
| 过期答案 | 无时间过滤；旧版本文档 | `updated_at`；版本淘汰 |
| 泄露他人数据 | ACL 未进检索 | 身份过滤；渗透测试 |
| 长文档抓不住 | 切片切碎要点 | 层级检索（先路由文档再段） |
| 表格算错 | 文本化丢失结构 | 专用抽取或工具算 |
| 慢且贵 | k 太大；上下文太长 | 重排后减 k；摘要索引；模型分级 |

---

## 6. 评测（RAG 专属）

至少分四类题目：

1. 语料内可答（应引用正确）  
2. 语料外（应拒答或澄清）  
3. 权限边界（不该看见的）  
4. 对抗/诱导忽略规则  

指标例子：引用正确率、拒答正确率、忠实度（是否编造）、端到端任务成功率。  
详见 [评测 Eval 与 Guardrails](./评测Eval与Guardrails.md)。

---

## 7. 参考架构要点（文字版）

- **在线路径**：查询 → 鉴权 → 检索（过滤 ACL）→ 可选 rerank → 生成 → 输出过滤 → 审计日志  
- **离线路径**：解析 → 清洗 → 切片 → 嵌入 → 索引 → 质量抽检  
- **反馈路径**：用户点踩 / 坐席修改 → 进入评测集与文档缺口列表
